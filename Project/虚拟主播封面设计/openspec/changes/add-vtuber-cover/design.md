# 设计 · 虚拟主播视频封面

## 一、为什么这么切

**仓库只放规矩，图放工作目录。** 仓库是公开的、按文本管理，图片进去会把体积和历史撑坏；而且封面属于天天变的产物，规矩才是要沉淀的东西。所以仓库里 `Project/虚拟主播封面设计/` 只有 README、主体档案、openspec 四件套；图全在 `E:\2026.07.13 190647 YKHR封面集合\AI封面工作目录`。

**四个能力分开写。** 出图流程管动作，风格库管素材，文案与版式管判断，交付管记账。四件事的变更频率不同，合成一本会互相拖累。

## 二、两段式怎么落地

底图先出、先存，文字后叠。好处是返工成本低：底图被否只重出底图，文字被否只重做文字层。文件名里底图带风格编号与日期，成品带主体简称与风格编号，两边能对上，便于追。

底图阶段一律不带字。模型爱在画面里写字，尤其爱写年份和伪 logo，所以底图验收只看一条，有没有可读字符，有就重出。

## 三、4:3 怎么不返工

这次先做 1920×1080，下一阶段改 1440×1080。做法是让所有版式硬线在两种比例下都成立：

1. 文字不触四边，按较窄的一边算安全边，两种比例通用。
2. 出 16:9 底图时，心里先套一个居中的 4:3 框，主体与文字都要落在这个框内。落在框外的部分在 4:3 阶段会被切掉。
3. 换 4:3 时不重排版式，只重出或裁切底图，字位按同一套硬线重算。

这样切比例的成本落在底图上，不落在规矩上。

## 四、版式为什么只写判据

写像素坐标的规矩，换画布就废，换主体也废。判据能活下来：不触边、不压脸、缩略图可读、字形不变形、对比够、有呼吸余量、只有一个重心。这七条在 16:9 与 4:3、在竖构图与横构图里都成立。

代价是执行方每次要自己判断字位。这个代价可以接受，因为风格卡已经给了字区方向，判据负责兜底。

## 五、风格库怎么分

上游参考库按内容分成七栏，其中真人杂谈与真人演出各只有个别样本，合并成一类「真人向」，其余照原样：唱歌、游戏、杂谈与切片、整活与活动、MV。六类各两套，一共十二套，编号 `CV01` 到 `CV12`。

`CV` 前缀是为了和别的项目的编号体系不撞。编号只增不回收，停用的号不复用，避免记录对不上。

风格卡固定八项，其中「与其他风格的差异」是防同质化的闸门，必须点名一套已有风格说清差在哪。只换颜色、只换照片的不算新风格。

## 六、名字为什么单列档案

两位主体的名字都是日文，写成简体、漏一个字、加个后缀，都是硬错。所以名字、账号、身份定位、常做内容全部落成档案，出图先读档案，画面上一律日文原名，账号不进画面。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 模型在底图里写字、伪 logo、假界面 | 底图验收只看可读字符，有就重出，最多三次后换提示词 |
| 生成写实人脸冒充本人 | 只用档案登记的官方形象或用户素材，生成了可辨认人脸一律弃用 |
| 日文字体缺字，`優`、`はる` 排不出来 | 用覆盖日文假名与常用汉字的字体，出图前先打一行名字试排 |
| 十二套看着像一套 | 差异项必须点名对比；同一类两套之间至少差两个维度（景别、光、构图、有无人物） |
| 4:3 阶段切掉主体 | 出 16:9 时先套 4:3 中心框预检 |
| 体积超平台上限 | PNG 控 4 MiB 内，另出同尺寸 JPG 控 2 MiB 内 |
| 风格库越加越乱 | 加货必须说明差异维度，停用不删卡 |

## 八、不做什么

- 不写像素坐标表。
- 不做自动抠图、自动排版脚本，这一版只定规矩与建库。
- 不碰参考库与素材目录里的任何原件。
- 不继承其他封面项目的配色、口号、行业清单、受众口径与文案骨架。
