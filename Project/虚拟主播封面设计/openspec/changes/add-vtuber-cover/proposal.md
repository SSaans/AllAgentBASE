# 提案 · 虚拟主播视频封面设计

## Why

两位主体（柊優花、東雲はる）的视频封面目前没有规矩，每次都要现想，出来的东西不成体系，也没法攒下来复用。仓库里已有的会议封面子项目只提供骨架，它的配色、口号、行业词与受众口径全部绑在另一个品牌上，搬不过来。

## What Changes

- 新建子项目 `Project/虚拟主播封面设计`，仓库只放规范，图与风格库放工作目录 `E:\2026.07.13 190647 YKHR封面集合\AI封面工作目录`。
- 建四个能力规格：出图流程、风格库、文案与版式、交付存档。
- 建主体档案，落两位主体的名字写法、账号矩阵与各平台定位，出封面时按档案取用，不许改写名字。
- 建风格库，按内容类型分六类（唱歌、游戏、杂谈切片、整活活动、MV、真人向），先建十二套，编号 `CV01`–`CV12`，配索引与轮转记录。
- 出图分两段，先出无字底图并存档，再叠文字另存，两段互不牵连。
- 尺寸先做 1920×1080 横屏；后续改 4:3 横屏时只换画布，版式判据不变。
- 版式与文案只写硬线与判据，不写像素坐标。
- 明确不继承项：原会议封面子项目的配色、口号、行业清单、受众口径、风格编号体系、文案骨架，一概不带入；本项目文件内不出现该品牌名。

## Capabilities

### New Capabilities

- `cover-render`：封面出图的两段式流程、画布规格、底图无字约束、底图与成品的对应关系。
- `style-library`：风格库的结构、风格卡字段、索引与轮转规则、加新风格的条件。
- `copy-and-layout`：主体档案（名字写法与账号用途）、文案判据、版式硬线与缩略图可读判据。
- `delivery`：产物命名、分段存档位置、交付前自检清单、改稿版本规则。

### Modified Capabilities

无。本子项目此前没有规格。
