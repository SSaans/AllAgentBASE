# 交付存档 · Delta

## ADDED Requirements

### Requirement: 工作目录分四格

系统 SHALL 把东西放在工作目录的四格：`风格库` 存风格卡与索引，`底图` 存无字底图，`封面输出` 存成品，`主体档案` 存两位主体的资料。仓库里不放图片，也不放档案副本。

#### Scenario: 出一张封面

- **WHEN** 底图与成品都做好
- **THEN** 底图落底图目录，成品落封面输出目录，风格卡改动落风格库目录

#### Scenario: 仓库自查

- **WHEN** 查看本项目在仓库里的内容
- **THEN** 只有 README 与 openspec，没有 png、jpg、psd，也没有档案目录

### Requirement: 文件命名可追溯

系统 SHALL 用两套命名：成品沿用既有交付习惯，写作 `【封面16:9】<视频标题>.png` 与 `【封面4:3】<视频标题>.png`；底图写作 `CVxx-日期-版本.png`，段间用连字符。成品与底图的对应关系记在索引里。

#### Scenario: 存成品

- **WHEN** 交付一条标题为「社恐怎么办？小春教你三招变“社恐”」的封面
- **THEN** 文件名为 `【封面16:9】社恐怎么办？小春教你三招变“社恐”.png`，4:3 版只改前缀

#### Scenario: 存底图

- **WHEN** 用 `CV07` 在 2026 年 10 月 31 日出底图
- **THEN** 文件名为 `CV07-20261031-v1.png`

#### Scenario: 底图与成品对上

- **WHEN** 出一组底图与成品
- **THEN** 索引里同一行记住两个文件名，任一方能查到另一方

#### Scenario: 主体简称

- **WHEN** 索引里要区分是谁的封面
- **THEN** 用档案登记的简称 `YUKA` 或 `HARU`，简称只进索引，不进文件名

### Requirement: 改稿不覆盖

系统 SHALL 每次改稿新增版本号，已交付版本原样保留。

#### Scenario: 第二次改稿

- **WHEN** v1 已被采用，用户要求调整
- **THEN** 出新文件 v2，v1 不动

#### Scenario: 同一版本只改文字

- **WHEN** 底图不变只改字
- **THEN** 版本号仍加一，文件名里的风格编号不变

### Requirement: 交付前自检

系统 SHALL 在交付前逐项确认：尺寸与色彩正确、文件体积在限内、名字写法与档案一致、缩进 320×180 后主标可读、本次风格与上次不同号、底图内无可读字符、账号未进画面。

#### Scenario: 自检有一项不过

- **WHEN** 任一项不满足
- **THEN** 修完重出，不带着已知问题交付

#### Scenario: 体积超限

- **WHEN** PNG 主文件超过 4 MiB
- **THEN** 压到限内再交；另出一份同尺寸 JPG 供平台上传，不超过 2 MiB

### Requirement: 工作目录边界

系统 SHALL 只在工作目录内写产物，不改动参考库与素材目录里的任何文件。

#### Scenario: 目录不存在

- **WHEN** 工作目录里缺底图或封面输出目录
- **THEN** 就地新建，不往参考库里挪文件腾位置

#### Scenario: 需要整理旧文件

- **WHEN** 觉得旧产物该清
- **THEN** 不删、不移、不改名，只报告，等用户决定
