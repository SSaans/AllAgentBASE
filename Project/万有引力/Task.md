  - 要做：① 在**仓库之外**建隔离环境（**不得污染系统 Python**）；
    ② 按**修正过的**依赖清单安装 —— 用 `requirements-deploy.txt`，**不要**用上游 `requirements.txt`
    （原因见该文件头部注释：上游那三处会装不上 / 跑不起来）；③ 装完先 `pip check`，再跑 `tools/verify_env.py`。
  - ⛔ 不得把 venv、依赖产物、任何输出目录放进仓库（`BRD.md` §七 `C4`）。
  - 证据：环境位置 + `pip freeze` 结果 + 自检输出（「依赖模块」一节须全 `OK`）。
  - 去向：开发 Agent → 测试 Agent（并入任务 9 一起复验）。

- [ ] 任务 1：**微信 4.x 取密钥**（开发 Agent）
  - 要做：对着**正在运行**的 4.x 微信取密钥；**全程只读**，不碰任何数据文件。
  - ⛔ 别用 3.x 的老办法硬套 —— 4.x 的取密钥方式变了。
  - 判据：能稳定取到密钥即通过；取不到就**停下，别往下硬走**，把报错原文写进 CHANGELOG。
  - 证据：**完整命令 + 完整输出**（密钥本身打码，只报「取到 / 未取到」）。
  - 去向：开发 Agent。

- [ ] 任务 2：**微信 4.x 解密出合法 SQLite**（开发 Agent）—— 🔴 **本项目当前的关键瓶颈**
  - 背景：上次走到这一步**失败**了，产物报 `sqlite3.DatabaseError: file is not a database`。
    含义是**要么密钥不对，要么解密没真正生效**。
  - 要做：先用**最小样本**（单个小库）验证解密流程，**不要**一上来就全量解密。
  - 🔴 **通过判据（硬）**：解密产物能被 `sqlite3` 正常打开、`sqlite_master` 表结构可读、能查到至少一条真实联系人。
    **只跑完不报错不算通过。**
  - ⛔ 输出目录**必须在仓库之外**。
  - 证据：**命令 + 报错原文（失败时）/ 表结构输出（成功时）**，写进子项目 CHANGELOG。
  - 📌 失败也要交：**可复现的命令 + 报错原文**，这是给后来者省时间的（`BRD.md` §八 `H3`）。
  - 去向：开发 Agent → 测试 Agent。

- [ ] 任务 3：**列出账号下的全部会话**（开发 Agent）
  - 前置：任务 2 通过。
  - 交付：能列出会话清单（数量 + 名称），不崩、不卡死。
  - 证据：会话数量 + 前若干条示例（**打码处理，不写真实姓名**）。

- [ ] 任务 4：**导出单个会话为 HTML**（开发 Agent）
  - 前置：任务 3 通过。
  - 交付：指定一个会话，导出 HTML，**文本 / 图片 / 时间轴**正常渲染。
  - 证据：产物路径（**仓库外**）+ 浏览器打开检查结果。

- [ ] 任务 5：**散落脚本的认领与正式化**（开发 Agent）
  - 背景：历史上留下的功能脚本有两处 —— ① 项目 `tools/` 下两个脚本（尚未规范化）；
    ② **仓库根目录一批未入库的临时脚本**，指向的输出目录**已不存在**，属交接缺口。
  - 要做：① 认领 `tools/` 下两个脚本（🔴 **已定案：正式化，不重写**）；
    ② 对仓库根部那批临时脚本**逐个判定**是规范化入库还是废弃。
  - ⛔ **清理任何文件都必须先列完整清单并经用户明确同意**（平台红线），Agent **不得自行删除**。
  - 证据：文件清单 + 处置结论 + `git diff --cached --name-only` 输出 + 敏感词自查结果。
