## [2026-09-20] 规划 Agent — 立项：万有引力（跨平台个人聊天记录归档）

**完成的工作**

- ✅ 按用户指派立项 `Project/万有引力/`：把散落各平台的**本人**聊天记录收拢到一处，归一为统一模型后导出可长期保存的格式。
- ✅ 产出四件：`BRD.md`（目标 / 边界 / 架构 / 模块划分 / 平台优先级 / 风险 / 四类验收标准）、`README.md`（大白话版）、`Task.md`（任务看板）、本文件。
- ✅ **架构主张落定**：`采集 → 解析 → 统一模型（枢纽） → 导出 → 应用` 五层；**唯一需要守住的纪律是「导出层永远不知道数据来自哪个平台」**，否则项目退化成"抓取脚本合集"。
- ✅ **平台优先级与依据**（含三处独立判断）：
  - **微信 P0** —— 本地加密库，读进程内存取密钥后解密，链路已跑通（待复验）。
  - **QQ / TIM P1** —— 同一个 NT 内核，**做 QQ 等于顺带做了 TIM**，性价比最高。
    🔴 同时否证一条捷径：NapCat / Lagrange 这类协议端只能拿到**服务端保留的历史**，
    腾讯服务端不长期存聊天记录 → **拿不全**；要完整历史**仍须解密本机 NT 数据库**。
  - **B 站私信 P2** —— **它其实比抖音可行**：私信在服务端、可翻页拉取，**不需要本地逆向**；
    难点是非公开接口 + 风控。用户"短期希望较低"的谨慎**合理**，但从技术难度上排在抖音之前。
  - **抖音 P3** —— 签名复杂、风控最强、合规风险最高 → **长线探索，不作为任何阶段的交付承诺**。
- ✅ **边界写死 6 条**（本人账号本人设备 / 不批量抓群成员 / **不提供找回已删除消息** / 原库只读 / **仓库只存代码不存聊天记录** / 不上传分享出售）。
- ✅ **§六 与 ALLBot 任务 36 划清界限**：那个是**群内 Bot 插件**（引用合并转发 → 回 HTML），
  本项目是**离线提取本机完整历史**；共同点只有"产物是 HTML"，代码与数据源不重叠。
