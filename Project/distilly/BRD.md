## 一、目标与范围

**目标**：用上游项目 Distilly，把用户本人的历史材料（聊天、文档、邮件、备忘、截图）**整理成一套可复用的 Skill** —— 即「我自己」的技能包；装进本机 Agent 宿主后，让 Agent 用用户的表达习惯与判断方式说话做事，并建立可持续追加、可回滚、可评估的迭代流程。

**产出形态**：一个 **Person Profile 技能包**（`SKILL.md` + `work.md` + `persona.md` + `work_skill.md` + `persona_skill.md` + `manifest.json` + `meta.json`），由宿主里现成的大模型加载后按你的风格工作。

**范围边界**：
- ✅ 本项目**就是做 Skill**。不涉及模型训练、不微调、不产出权重文件（用户 2026-09-20 已确认）。
- ✅ 本项目**不开发新功能**：全部能力来自上游，本仓库只放文档与规划，不复制上游源码。

### 3.2 核心机制（四层）

1. **采集层**：五种入口 —— Ⓐ 飞书自动采集（推荐）· Ⓑ 钉钉自动采集 · Ⓒ 飞书链接 · Ⓓ 上传文件（PDF / 图片 / 导出 JSON / 邮件 `.eml/.mbox`）· Ⓔ 直接粘贴。
2. **分析层**：两条线并行 —— **Work 线**（职责系统、技术规范、工作流程、输出偏好、经验知识）与 **Persona 线**（表达风格、决策模式、人际行为）。`celebrity` 家庭额外跑 **6 维度研究**（著作 / 对话 / 表达 DNA / 决策 / 他者视角 / 时间线），并有 `audit → synthesis → validation` 三重关卡。
3. **产出层**：一律走 `skill_writer.py` 落盘，生成 **7 个文件**：`SKILL.md`、`work.md`、`persona.md`、`work_skill.md`、`persona_skill.md`、`manifest.json`、`meta.json`；落在 `./skills/{family}/{slug}/`，可选一步装进宿主。
4. **进化层**：追加材料 → `merger` 合并；对话纠错（「这不对 / 他应该是」）→ `correction_handler`；每次变更前 `version_manager.py` 备份，支持回滚。

### 3.3 三种「人」的类型（character family）

| family | 适合谁 | 额外模块 |
|---|---|---|
| **`colleague`** | 同事、上级、导师、自己 | Persona 六层 + **Work Skill**（职责范围 / 工作流 / 输出偏好 / 经验库） |
| `relationship` | 恋人、家人、老友 | 表达 DNA · 情绪触发 · 冲突模式 · 修复模式 |
| `celebrity` | 公众人物、创作者、虚构角色 | 心智模型 · 决策启发式 · 表达 DNA · 他者视角对照 + 六维研究档案 |

> **「蒸馏自己」落在 `colleague` 家庭** —— 因为「自己」天然同时具备「工作方法」与「人格表达」两块，正好对应 `colleague` 的 Work + Persona 双层结构。

## 四、适用场景

**合适**
- 把散落的个人材料变成**可长期复用的「我」**：Agent 用你的口吻回消息、按你的套路写文档做决策。
- 个人知识资产沉淀：把「我的判断标准、我的做事流程」显式化，可交付给他人或未来的自己。

**不合适**
- 手里几乎没有材料、只写一句性格描述 —— 产出会非常薄（上游对材料稀薄场景有「冷门人物协议」降级，但降级仍是薄）。
- 期待 100% 复刻人格 —— 上游明确不承诺（自述「does not claim to clone the person」）。

## 五、「蒸馏自己」的落地映射（关键差异点）

1. **family 选 `colleague`**（不用 `celebrity`，也不建议用 `relationship` 来蒸馏自己）。
2. **数据入口只走 Ⓓ 上传文件 + Ⓔ 直接粘贴。**
   上游的 Ⓐ/Ⓑ/Ⓒ 全部是**飞书 / 钉钉 / Slack 专用采集器**，本机日常是 QQ / 微信 → **没有现成采集器，必须自己把材料整理成文件**：
   - 可用：邮件 `.eml/.mbox`（`email_parser.py` 支持）、Markdown / TXT 直读、PDF 直读、聊天截图（宿主 Read 原生读图）、手动整理成 txt。
   - 不可用（无采集器）：微信、QQ 的历史消息自动拉取。
   - ⚠️ 这是本项目**最大的工作量所在**：数据整理的工程量 > 蒸馏本身的工程量。
3. **产出物 = 一个「你自己」的 Skill**，装到宿主后即可用你的风格工作。
4. **评估要自建**：上游的自动质检（`research/quality_check.py`）**只对 `celebrity` 的 `source_grounding` 生效**；`colleague` 家庭没有自动质量门 → 评估方案必须自己定（见「十、效果验证与评估」）。

## 八、个人数据准备：范围与格式

> 原则：**来源越一手越好，时间跨度越长越好，材料类型越杂越好**（聊天看表达，文档看方法，决策记录看判断）。

| # | 材料类别 | 典型来源 | 目标格式 | 采集方式 | 清洗要求 | 优先级 |
|---|---|---|---|---|---|---|
| 1 | **表达样本**（口吻） | 聊天记录、群聊、朋友圈、邮件正文 | 纯文本 `.txt` / `.md`，按时间排序，标注语境 | 手工导出 → 手动整理；截图可直读 | 剔除他人隐私、群名、手机号、地址 | ⭐⭐⭐ |
| 2 | **工作方法** | 技术文档、方案、周报、README、笔记 | `.md` / `.txt` / `.docx` | 直读或 `python-docx` | 剔除公司机密、内网地址、客户名 | ⭐⭐⭐ |
| 3 | **判断与决策** | 技术选型记录、复盘、评审意见 | `.md` / `.txt` | 手动整理 | 保留「为什么这么决策」的理由链 | ⭐⭐⭐ |
| 4 | **邮件** | 往来邮件 | `.eml` / `.mbox` | `email_parser.py` | 过滤签名档、附件链接、他人姓名 | ⭐⭐ |
| 5 | **表格类** | 排期、清单、台账 | `.xlsx` / `.csv` | `openpyxl` | 去掉含真实数据的行列 | ⭐ |
| 6 | **截图** | 聊天/文档截图 | `.png` / `.jpg` | 宿主 Read 直读 | 打码敏感处 | ⭐ 起补充作用 |
| 7 | **自我描述** | 手写三问答案 | 文本（intake 时直接输入） | 粘贴 | — | ⭐⭐⭐ |

**格式硬要求**
- 编码统一 **UTF-8（无 BOM）**；文件名避免特殊符号。
- 单文件建议 **≤ 200KB**，超大材料按「主题/年份」切分，避免推理时读不全。
- 每份材料**开头三行写元信息**：`来源` / `时间范围` / `敏感级别`。
- **涉及他人的材料必须脱敏**（姓名可代称、群名可编号）——既是隐私要求，也避免产出物带上他人信息。

**隐私分级（必须在阶段 2 定死存放边界）**
| 级别 | 内容 | 存放 | 能否入库 |
|---|---|---|---|
| L1 公开 | 公开文档、通用技术笔记 | `knowledge/self/public/` | 可（仍建议不入库） |
| L2 内部 | 工作文档、方案 | `knowledge/self/internal/` | ❌ 不入库 |
| L3 私密 | 聊天记录、邮件、含他人信息 | `knowledge/self/private/` | ❌ 不入库，且建议加密容器保存 |

> 🔴 本仓库曾在 `data/` 下出现过含 API Key 的未跟踪文件（尚未裁决），**本项目所有材料一律放在仓库外的 `D:\Program\distilly\knowledge\`，绝不进 git**。产出物 `skills/` 含个人画像，同样不入库。

## 十、效果验证与评估

> ⚠️ 上游**没有** `colleague` 家庭的自动质检（`quality_check.py` 只查 `celebrity` 的 `source_grounding`）→ 评估必须自建。

### 10.1 客观项（可机检）
| 项 | 判据 |
|---|---|
| 产物完整性 | 7 个文件齐全，无空文件 |
| schema 合法性 | `meta.json` 含 `name` / `display_name` / `character=colleague` / `classification.language=zh-CN` / `profile` / `tags` / `knowledge_sources` |
| 可枚举 | `skill_writer.py --action list` 能列出该 skill |
| 可装载 | 宿主被明确告知该技能存在，且能被触发 |
| 版本可回滚 | `version_manager.py` 能列出并成功回滚到上一版本 |

### 10.2 主观项（人工评分）
| 项 | 方法 | 及格线 |
|---|---|---|
| **已知答案题（known-answer）** | 出 **≥ 5 题**「只有我自己知道答案」的问题（如某次技术选型的理由、某个流程的具体顺序），对比产出回答与我的真实答案 | ≥ 4/5 关键点命中 |
| **陌生场景题（edge-case）** | 出 **2 题**我从未写过答案的新问题，看它的推理路径是否「像我会走的」 | 用户主观认可 ≥ 及格 |
| **口吻盲测（voice check）** | 取我的 5 段真实回复 + 产出 5 段同题回复，**打乱顺序让第三人指认哪些是我写的** | 混淆率 ≥ 40%（说明确实像） |
| **一致性 rubric** | 5 维打分：口吻像不像 / 决策像不像 / 知识对不对 / 有没有出戏 / 会不会过度自信 | 每维 1–5 分，均分 ≥ 3.5 |
| **负样本检查** | 故意问 1 个「我一定会拒绝」的要求，看它是否也会拒绝 | 行为一致 |

### 10.3 进化回归
- 追加材料后：**known-answer 分数不得下降**，且原先正确的条目未被改写坏。
- 每轮进化后有版本快照，出问题可一键回滚。
