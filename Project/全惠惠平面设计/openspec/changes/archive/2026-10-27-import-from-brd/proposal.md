# 提案

## Why

这个项目每天都要出三组朋友圈内容，BRD 写了八百多行，视觉规范、文案红线、风格参考、七条硬规则散在十几个小节里。执行方每次开工要重读一遍才敢动手，还容易漏掉其中某一轮用户纠正过的口径。

## What Changes

把「做出来的东西必须满足什么」拆成四个能力，每条配场景。风格参考库、历次口径纠正留在 README 与规范卡里。

- 每日三图：早中晚各一组，交付可追溯
- 出图管线：文字层由程序叠加，不让模型画中文
- 文案：同主题、泛用、不编造
- 视觉规范：logo、字体、色彩

## Capabilities

### New Capabilities

- `每日三图`: 每天三组内容的生产与交付规则
- `出图管线`: 背景与文字层的分工，成品的硬性技术要求
- `文案`: 配文的取材、语气与合规边界
- `视觉规范`: logo、字体、色彩与版面层级

### Modified Capabilities

无，首次建立基线。

## Impact

- `BRD.md` 退役，行为进 `openspec/specs/`
- 视觉规范卡、文案素材池、出图说明保留为执行资产
- 设计资料目录只读引用，原件不入库
