## 〇、先看这段：这个项目怎么用

### 0.1 一句话指令

用户日常只会丢一句话过来，比如：

> 「做个 logo 片尾」
> 「出个 logo 动画，十秒左右」
> 「老板要个宣传片，讲我们公司做什么的」

这一句就是工单，收到之后按第一章走。

业务信息不全才去问（给谁看、要多长、什么时候要、放哪儿播）。技术参数自己定。

### 0.2 五条规矩

| # | 规矩 | 为什么 |
|---|---|---|
| 1 | 一次过，不试错 | 视频按秒算钱，返工成本是平面图的几十倍 |
| 2 | 文案和分镜先定，再开生成 | 生成完再改一个字，等于整段重来 |
| 3 | 只做生成，不做剪辑 | 画面由代码画出来，不剪别人拍的素材 |
| 4 | 同一镜头最多两次 | 两次不成换路子，别硬磕 |
| 5 | 不主动多做一版让人挑 | 做一条就是一条 |

### 0.3 三个路径

## 一、一条片子怎么出来

### 第 1 步 · 把话翻成需求卡（限 500 字）

见第五章。这一步不做完，后面不动。

### 第 2 步 · 定怎么画

先想清楚这段画面由几部分组成：背景、光、主体、文字。每一部分用什么方式画，用代码还是贴图。想不清楚就先出静帧试。

详见第八章。

### 第 3 步 · 文案和分镜

- 文案按第六章写，先定稿再动画面
- 分镜拆成几个镜头，每个镜头写清：画面内容、镜头怎么动、多长、有没有字
- 落成 `镜头清单-v1.md`，一个镜头一行

后面用户说「第三个镜头换掉」，就只重出那一个，其余不动。

### 第 4 步 · 找参考、定参数

动手写代码之前，先看同类东西怎么做：

- 大品牌怎么做 logo 动画（片尾定格停多久、光从哪来、多长时间）
- 这些效果拆开是什么：渐变、模糊、粒子、位移

参考给自己看，用来把「大气」「高级」翻成色值、像素、帧数、缓动曲线。第八章 8.4 有对照表。

### 第 5 步 · 渲染、验收、归档

写脚本算出每一帧，存 PNG 序列，ffmpeg 压成 mp4。先出五张静帧给人看，对了再渲染全片。

交付三样：成片、脚本、一句说明（多长、什么规格、改了哪里）。脚本要留，下次改文案要重跑。

按第九章命名，放当天文件夹。

## 二、公司是干什么的，给谁看

### 2.1 业务四块

| 板块 | 一句话 |
|---|---|
| 直销 | 靠人脉和信任成交，视频会被人转来转去 |
| 开会讲课 | 公司的主场。会议、培训、招商、表彰，视频素材的大头 |
| 房产 | 管得最严，一句话说错就出事 |
| 购物平台 | 讲省钱、讲聚合、讲商家入驻 |

公司全名 **全惠惠**。旧名「全商汇」已经作废，见到这三个字一律按全惠惠处理（老素材文件名里还有，别照着念）。

### 2.2 受众决定一切

看片子的人，四十岁以上占大头，**董事长七十多岁**。

所以：

- **字要大。** 手机上看得清，会议室大屏上更得看得清
- **节奏别太快。** 三秒一个镜头那种剪法，四十岁往上的人跟不上，看完只记得晃
- **话说直白。** 不玩梗、不用网络流行语、不写英文缩写
- **一条片子说一件事。** 又要讲模式又要讲产品又要讲愿景，最后一样都记不住
- **气派要足。** 这一代人认「有排场」：红毯、金色、光效、鼓点、大场面。冷淡极简那套在他们眼里叫「没做完」

### 2.3 经营理念：文案的底料

核心理念八个字，一切从这儿长出来：

> **全心全意聚商机　互惠互利赢未来**

往下一层是三为方针：**为消费者省钱、为商家引流、为事业伙伴创造价值。**

## 三、这个 Agent 叫什么，干什么

### 3.1 名义是「开发」，实际是「执行」

这个项目在仓库里的角色名叫**开发 Agent**，但它**不写一行功能代码**。

它干的活是：

| 干 | 不干 |
|---|---|
| 把片子做出来：写文案、排镜头、写提示词、盯模型出片、验收 | 不写播放器、不写后台、不搭服务 |
| 写渲染脚本，把画面算成帧 | 不开发工具、不写脚本框架 |
| 出策划案、分镜表、文案 | 不改别的项目一个字 |
| 挑模型、盯质量、把残次品挑出来重来 | 不碰命令行，不折腾剪辑软件 |

一句话：交付物是能直接用的片子、提示词、策划案，不写代码。

### 3.2 边界（写死，不许商量）

| 对象 | 能不能碰 |
|---|---|
| 本项目目录（`Project/全惠惠视频制作/`） | ✅ 随便写，狠狠写，规划做厚 |
| 平面设计项目（`Project/全惠惠平面设计/`） | ❌ **一个字都不许改**，包括错别字、格式、归档 |
| 仓库其他任何子项目 | ❌ 一个字都不许改，一行代码都不许写 |
| 设计资料目录 | ✅ 只读。**不许改、不许删、不许复制进仓库** |
| 既有视频 | 旧的会议片和片头素材，只读。要用里面的音乐可以，别拿它当风格模板 |
| 根 `openspec/specs/` / 根 `CHANGELOG-历史.md` | ❌ 不碰。本项目的立项索引由平台级统一补 |

**越界了怎么办**：停手，写进本项目 `openspec` 登记，说明该谁做，然后交出去。

### 3.3 学平面设计项目，只看不改

它的 README 值得读。一句话进来，怎么一路走成成品，写得清楚。

这边学的是写法：指令短，步骤明确，参数事先定好，交付只说一句。

它自己那套做法（每天三套、轮转挑风格、五段式配文）是它产品形态的产物，不往这边搬。哪些能借、哪些不能借，第十二章写清了。

**不许做的事**：改它的 README 说「顺手优化」，把它的模板复制过来改几个字，把它归档里的成品挪走。

## 四、长什么样

### 4.1 大方向

**大企业调性**：稳、正、有分量。看完让人相信这是一家正经公司，不是微商，不是野生团队。

同时要有宣传效果：别做成内部会议纪要那种平铺直叙，得让人看完想了解一下、想加入、想合作。

做法是画面稳、节奏有起伏，话不多但每句都有落点。

### 4.2 交付规格

之前那条 logo 片尾的技术参数，可以当尺寸参考：

| 项 | 值 |
|---|---|
| 时长 | 11 秒 |
| 分辨率 | 1920×1080 |
| 帧率 | 25 fps |
| 编码 | H.264 / yuv420p |
| 音频 | AAC 48kHz |

时长和画幅按需求定。竖版给朋友圈就 1080×1920，大屏就横版，别自己套死。

> 说明一下：之前那些会议片是老板自己拿剪辑软件手工剪的，跟这边用模型生成不是一条路，参考价值不大，不必去翻。

### 4.3 生成时的六条准则

1. 画面里的字越少越好。必须出现的时候，一行说一件事，字号要大
2. logo 用原图直接嵌进去，不重绘、不描边。代码贴图不会有误差
3. 不用花哨东西：乱飞的光斑、故障风、快闪、鬼畜、卡通小人、荧光色
4. 不玩梗，不用网络热词和谐音
5. 一屏一句话。12 个字是个参考值，用户提了具体要求就按他的来
6. 结尾给品牌留个位置。11 秒的片尾本来就在讲品牌，不用另外再加一层

### 4.4 不碰的清单

荧光色、糖果色、卡通风、网红夸张风、一层叠一层的花哨渐变、公文简报式排版、可辨识的异地地标（公司在中山，不拿东方明珠当背景，也不把生成画面叫中山实景）。

## 五、需求怎么进来：把领导的话变成 500 字

### 5.1 为什么要有这一步

领导说「搞个大气点的视频」，这句话能派生出二十种做法，每一种都要烧钱。**不先把话捏实，后面全是返工。**

所以定了统一动作：任何口头要求，先落成一张**需求卡**，再动手。

### 5.2 需求卡：七个格子

```
【需求卡】<片子名>

1. 给谁看：
2. 看完要他干一件事：
3. 多长：
4. 必须出现：
5. 绝对不能出现：
6. 什么时候要：
7. 放哪儿播：
```

七个格子填满，**总字数不超过 500 字**。超了就砍描述、留事实。

填不出来的格子，才去问人。问也只问业务，不问技术。

### 5.3 「一岁小孩都能听懂」的四条改写法则

| 法则 | 做法 | 反例 → 改写 |
|---|---|---|
| 一句一事 | 一句话只装一个意思 | 「要体现我们的聚合赋能生态和多方共赢格局」→「讲清楚三件事：消费者省钱、商家来客、伙伴赚钱」 |
| 换成看得见的东西 | 形容词换成画面 | 「要大气」→「黑底、金字、慢推镜头、鼓点音乐」 |
| 砍掉模糊词 | 之类的、差不多、那个感觉、稍微、尽量 | 「稍微高级一点」→「去掉卡通元素，只留实拍和文字」 |
| 数字写死 | 长度、时间、数量全用数字 | 「别太长」→「60 秒以内」 |

### 5.4 一张写好的需求卡长什么样（样例）

```
【需求卡】logo 片尾动画 v1

1. 给谁看：会议大屏 + 视频号，四十岁以上为主，董事长也在看
2. 看完要他干一件事：记住「全惠惠」这个名字和那只红凤凰
3. 多长：11 秒（跟既有片尾一致）
4. 必须出现：红凤凰图形、书法体「全惠惠」、英文 QUANHUIHUI、
   核心理念「全心全意聚商机，互惠互利赢未来」
5. 绝对不能出现：AI 画歪的 logo、错字、花哨光斑、卡通元素、云纹
6. 什么时候要：明天下午
7. 放哪儿播：会议结尾大屏，也会嵌进快剪片尾

（共 168 字）
```

### 5.5 需求卡放哪

跟成片放一起：`<月日>\需求卡-<片子名>.md`。

改需求就在原卡上改，改完在下面追一行「改了什么 · 日期」，不要另建新卡。

## 六、文案：这个项目的一半活

**多数情况下，片子好不好看取决于文案。** 画面能生成，话得有人想。

### 6.1 字数怎么估

视频没法回看。一句没听清就过去了，所以话要短，一句只说一件事。

字数大致这么估：

- 字幕在屏幕上停两三秒，一眼能抓十来个字，两行封顶
- 人一口气能念十二到十五个字，再多换不上气
- 六十秒的片子按每秒两个字算，旁白一百二十字上下

这些是参考值，不是红线。用户提了具体要求就按他的来。

### 6.2 三种形态

| 形态 | 用在哪 | 字数参考 |
|---|---|---|
| 屏上大字 | 画面上的标语 | 一行十来个字，两行封顶 |
| 旁白 | 配音念的 | 一句十来个字 |
| 落版 | 结尾品牌条 | 全惠惠，全心全意聚商机，互惠互利赢未来。 |

屏上大字让人记住，旁白把事说清，落版署名。

11 秒的片尾，屏上八个字就够，旁白可以一句都不要。塞进去了反而把落版冲散。

落版句式平时照原句来。用户说改，那就改他的版本。

### 6.3 一条片子的骨架：开头、说事、收尾

开头几秒抓不住人，后面做什么都白搭。

| 段 | 位置 | 干什么 |
|---|---|---|
| 开头 | 前五秒 | 一句狠话，或一个大场面，或一个数字 |
| 说事 | 中段 | 只讲一件事，最多给三个理由撑住它 |
| 收尾 | 最后 | 一句记得住的话，加品牌 |

六十秒的片子，开头给五秒，说事占七成，收尾留八秒以上让人看清。

一条片子只讲一件事。模式、产品、愿景全塞进去，观众一样都记不住。

11 秒的片尾连说事这一段都没有，全靠画面演绎和八个字落版。片尾的文案活最轻，画面活最重。

### 6.4 从口号到画外音：转译三步

口号是印在横幅上的，看的时候可以慢慢品。念出来的话得顺口，所以中间要做一次转译。

| 步 | 做什么 | 例 |
|---|---|---|
| **留骨架** | 动词和数字不换，那是气势的支点 | 奋战一百天，冲刺一个亿 |
| **换语体** | 书面词换成嘴里说得出的词 | 「凝心聚力」→「大家一起使劲」 |
| **加落点** | 后半句落到一个具体动作 | 「冲刺一个亿」→「这个月，把单子签下来」 |

三步走完，原句的意思必须还在。**意思变了就是另写，不叫转译。**

**屏上大字直接用口号原句，不做转译。** 转译只用在旁白上。

### 6.6 写文案常犯的毛病

| 毛病 | 为什么不行 | 改成 |
|---|---|---|
| 一屏塞四行字 | 三秒读不完，等于没写 | 砍到两行，剩下的交给旁白 |
| 旁白念成汇报稿 | 「依托数字化工具优化商业链路」念出来没人懂 | 「让生意好做一点」 |
| 把理念整段搬上屏 | 念不完，记不住 | 只留八个字 |
| 通篇形容词 | 没有画面，做片的人无从下手 | 换成动作、数字、具体物件 |
| 编客户案例、编业绩 | 一问就露馅，还违法 | 只讲机制，不讲战绩 |
| 用英文缩写和行业黑话 | B端、GMV、生态闭环，四十岁以上的人不听这套 | 说人话 |
| 落版自己改句式 | 品牌署名是固定的一句，改了就不像公司说的 | 原句照抄 |

### 6.7 合规红线

视频说错话收不回来，比图文更严。

| # | 红线 | 具体 |
|---|---|---|
| 1 | 不承诺收益 | 不用「稳赚」「保本」「零风险」「一定能赚」「躺赚」 |
| 2 | 不用绝对化用语 | 不用「最」「第一」「唯一」「国家级」「顶级」 |
| 3 | 不编数据 | 不编业绩、人数、案例、客户评价 |
| 4 | 权益口径照原文 | 权益仅限本人后续消费抵扣使用，**不可提现、不可变现、不可转让** |
| 5 | 房产不承诺升值 | 不做投资回报表述，不说「必涨」「翻倍」 |
| 6 | 直销表述谨慎 | 不描述「拉人头获利」，只讲「按本人直接有效成交订单获取推广服务佣金」 |
| 7 | 不做功效暗示 | 大健康类不做医疗、保健功效表述 |
| 8 | 素材要有授权 | 音乐、字体、影像可商用；人物出镜要本人同意 |
| 9 | AI 画面不冒充实景 | 生成画面不说成「我们在中山的实拍」 |
| 10 | 口播风险最高 | 字幕还能删，声音进了别人耳朵就收不回。旁白定稿前多念两遍 |

**禁词块（定稿前扫一遍，命中就改）**

```
稳赚　保本　零风险　一定能赚　躺赚　暴利　包赚
最好　最大　最强　第一　唯一　顶级　国家级　世界级
保证收益　投资回报　必涨　翻倍　升值　增值空间
包治　根治　疗效　治愈　神奇　特效
提现　变现　转让（涉及消费权益时）
```

### 6.8 文案怎么交

跟片子放一起，文件名 `<月日>-<类型短名>-文案-v<N>.md`。

写什么看这次做的是哪种片子。起码记下四件事：

- 画面上出现哪些字，第几秒出现
- 有没有旁白，念的是什么
- 结尾怎么收
- 每句话从哪来（口号第几条，或者哪句理念变来的）

格式随意。三五行也行，按镜头逐条列也行，别为了套模板硬凑。

出处这一条别省。说不清从哪来的句子，删掉重写。

## 八、怎么出片

### 8.1 定下来了：用代码渲染

logo 片尾、片头、字幕卡这类纯图形的片子，用代码逐帧画，直接输出 mp4。

不用视频生成模型。三条原因：

- 贵。按秒或按次收费，一条十几秒的片子几十上百块
- 抽卡。同一个提示词跑两次结果不一样，改一处就得整段重来
- 中文字和 logo 画不准。这是模型能力的边界，提示词调不好

所以执行方拿到这个项目，只写渲染代码。**不要装 Runway，不要调视频生成接口，不要推荐用户订阅。**

以后要做人物、实景、大场面，再单独讨论。

### 8.2 技术栈

两条路线，挑顺手的：

| 路线 | 用什么 | 适合 |
|---|---|---|
| Python | PIL 画图、numpy 算光、imageio 或 ffmpeg 编码 | 大部分片子，够用 |
| 网页 | Canvas 或 Three.js 画，Playwright 逐帧截图，ffmpeg 编码 | 要 3D 感、粒子多的时候 |

ffmpeg 是个命令行工具，专门把一堆图片按顺序压成视频。本机有：

```
C:\Users\Unbox\AppData\Roaming\LottieViewConvert\ffmpeg\ffmpeg.exe
```

流程就三步：

```
① 写脚本，算出每一帧该长什么样
② 存成 PNG 序列，frame_0000.png 起
③ 用 ffmpeg 压成 mp4
```

压片命令，1080p 25 帧：

```bash
ffmpeg -framerate 25 -i frame_%04d.png -c:v libx264 -pix_fmt yuv420p -crf 18 -movflags +faststart out.mp4
```

### 8.3 能做和不能做

| 能做 | 做不了 |
|---|---|
| logo 演绎、光效、粒子、图形变换 | 真人出镜 |
| 字幕卡、数据图、文字动画 | 真实街景、办公室实拍 |
| 片头片尾、转场、色块排版 | 需要演员表情的镜头 |
| 任意时长，几分钟也行 | 复杂三维场景（成本高，另议） |

一句话：画得出来的都能做，要拍出来的做不了。

### 8.4 把要求翻成参数

领导说「大气」「高级」，代码听不懂。得翻成数值。

| 听到的 | 翻成 |
|---|---|
| 大气 | 主体占画面三分之一，四周留白 200 像素，镜头推近从 1.0 到 1.08 |
| 高级 | 背景亮度压到 12%，主光从左上 45 度进来，外发光模糊 30 像素 |
| 有科技感 | 深蓝底 #0B1420，细线网格透明度 8%，四十个光点随机游走 |
| 五彩斑斓的黑 | 黑底叠一层彩虹渐变，透明度 15%，加细噪点 |
| 稳重 | 全部用 ease-in-out，速度不超过每秒 40 像素 |
| 有冲击力 | 前 0.3 秒画面不动，第 0.3 秒突然放大一点五倍 |

规矩是：颜色给色值，位置给像素，时间给帧数，运动给缓动曲线。四样里至少说清三样。

### 8.5 缓存怎么命中

缓存只认一件事：这次请求的开头，跟上次是不是一模一样。换措辞、调顺序、在前面加新东西，都会让它失效。写代码这种活，同一个会话里连续改，前面的部分不动，就一直在缓存里。

定个固定顺序，每次照排：

```
S 段  系统包（提示词库第一节那段话，整段贴，别改字）
C 段  公司常量（理念、口号、颜色）
T 段  这次的任务（片子类型、时长、必须出现什么）
```

规矩五条：

1. S 段原样复制。不润色，不改标点，不调顺序
2. 新东西只加在最后，前两层不动
3. 一批活连着做，隔太久缓存就过期了
4. 要改流程文件，等这批交完再改
5. 这一轮读过的规范记着，别每改一版回去翻一遍

### 8.6 一次过

1. 文案定稿再动手写代码
2. 镜头表填满，每段都有画面、运动、时长
3. **先出五张静帧**，确认画面对了再渲染全片。275 帧白跑一次，比五张图贵得多
4. 渲染中途不改参数，要改就整段重来
5. 一条片子最多返两次
6. 不多做一版让人挑

### 8.7 卡住了怎么办

| 情况 | 处理 |
|---|---|
| 代码跑不通 | 先查报错，别急着改方案。二十分钟搞不定就停下来换思路 |
| 渲染出来难看 | 拿静帧对比参考，找出差在哪：光、色、构图、节奏 |
| 返了两次还不行 | 停下，交付说明里写清卡在哪，把脚本和静帧一起交出去 |
| 用户说「太烧了」 | 立刻停，回到只交方案 |
| 用户说「别搞了」 | 立刻停手，只交他点名那一件 |

### 8.8 音乐和音效

音乐三条路：

- 复用现成的，公司之前用过的那种大气感
- 用生成模型做一段，十几秒的短音效生成比找快
- 用免版权的素材库

音效跟着画面走：光起来一下，字幕落下一下，落版定住一下。别铺满，留白比铺满好听。

### 8.9 脚本要留档

代码渲染的好处是能改、能复跑。所以脚本必须留在成品目录里，跟 mp4 放一起。下次改一句文案，改两个参数重跑就行，不用从零再来。


## 九、命名与版本：v1、v2 怎么排

### 9.1 成品放哪

```

├── 10月17日\
│   ├── 10月17日-片尾logo-v1.mp4

│   └── 需求卡-片尾logo.md
└── 10月18日\
    └── ...
```

- 每天一个文件夹，日期写法固定「10月17日」，不写 20261017
- 当天所有产出都进当天文件夹
- **别的日期的文件夹一个字都不动**

### 9.2 版本号规则（跟平面设计项目同一套）

| 情况 | 版本号 |
|---|---|
| 同一天改稿 | 读出当天最大 `vN`，本次 `v(N+1)` |
| 新的一天 | 从 `v1` 起，不接着前一天加 |
| 文件夹是空的 | 从 `v1` 起 |

版本号是「这一天改了几稿」，不是「总共出了几版」。跨天归零。

### 9.3 改局部只重出那一段

平面图改稿整张重出。视频不用这么干，太贵。

改局部的时候，只重出受影响的镜头，其他段沿用上一版的，在生成工具里重新拼一次。所以：

- 每段单独存：`10月17日\片段\片尾-v1\s01.mp4`、`s02.mp4`……
- 整条另存一份：`10月17日-片尾logo-v1.mp4`
- 出新版，只换变了的那个片段，再拼一次

v1 到 v2 只改一句字幕，成本就压在一段上。

### 9.4 镜头清单

每个片子配一份 `镜头清单-vN.md`：

| 镜头 | 时长 | 画面 | 运动 | 屏上文字 | 状态 |
|---|---|---|---|---|---|
| s01 | 2.5s | 黑底，一点金光亮起 | 光点扩散 | 无 | v1 采用 |
| s02 | 3.0s | 凤凰轮廓由暗转亮 | 缓慢推近 | 无 | v1 采用 |
| s03 | 3.5s | 深色背景，中央留空 | 几乎不动 | 全惠惠 | v1 采用 |

改稿时只改这张表的一行，重出那一个镜头。哪一段返工多，也记在这儿，下次写提示词的时候提前防。

## 十二、借鉴与原创：界线划在这儿

平面设计项目跑在前面，方法值得学。但它是朋友圈日更，这边是按需出片，**两套产品逻辑，内容不能互相搬**。这一章把界线写死，免得后面越做越混。

### 12.1 两套逻辑的根本区别

| | 平面设计（朋友圈日更） | 视频制作（本项目） |
|---|---|---|
| 产品形态 | 每天固定三套，天天交 | 有需求才做，没有固定节奏 |
| 传播场景 | 朋友圈里被动划过，随时能划走 | 投在大屏上或点开播放，得看完 |
| 文案的角色 | 独立阅读物，可以慢慢读 | 时间轴上的零件，跟着画面走 |
| 结构的依据 | 社交节奏：问候 → 说事 → 收束 | 注意力曲线：钩子 → 说事 → 落点 |
| 成败判据 | 同行敢不敢原样转发 | 观众看没看完、记没记住 |
| 迭代单位 | 整张图重出 | 只重出受影响的镜头 |
| 成本量级 | 低，可以天天试 | 高，一次就得算准 |

根子上是**两个字**：朋友圈文案是拿来**读**的，视频文案是拿来**听和扫**的。读可以回看，听不能倒带。所以字数、句式、结构全都不一样。

### 12.2 借的是方法，不是内容

| 借鉴了什么 | 借的是哪一层 | 说明 |
|---|---|---|
| 一句话指令 + 固定步骤 | 组织方式 | 让执行方不用回头问人，照着走就行 |
| 硬参数写进文档 | 工作习惯 | 尺寸、字数、时长全定死，不靠临场判断 |
| 版本号跟日期绑、跨天归零 | 命名规则 | 直接沿用，这套规则本身跟内容无关 |
| 素材建库、用完回填 | 资产思路 | 建库的动作一样，库里装的东西完全不同 |
| 文案必须能溯源 | 纪律 | 说不清出处就删，这条对两种媒介都成立 |
| 交付只说一句 | 沟通口径 | 不甩文件清单、不甩路径表 |
| 文件分层：基座 / BRD / Task / CHANGELOG | 文档结构 | 仓库通用规范，不是哪个项目的私产 |

**借的是骨架，骨架里长什么肉，各长各的。**

### 12.3 本项目原创的部分

| 原创内容 | 怎么来的 |
|---|---|
| 三种文案形态 + 各自字数 | 从「停留时间」和「一口气长度」这两个生理上限反推出来的，见 §6.1 |
| 钩子 → 说事 → 落点 | 视频注意力曲线的结构，11 秒片尾直接砍掉中段 |
| 代码渲染这条路 | 成本低、可复跑、中文和 logo 不走样 |
| 关键帧打底 | 把「画什么」和「怎么动」拆开，压住模型的自由发挥 |
| 镜头级版本迭代 | 视频贵，改局部不能重出整片 |
| 缓存 S/C/T 三段 | 从计费规则反推的写法，跟排版毫无关系 |
| 技术基线（11 秒 / 1080p25 / 13.7Mbps） | 拿既有片尾实测出来的，不是估的 |
| 需求卡七格 | 对付领导口头要求的闸门，视频专用 |
| 视频合规四条新红线 | 音乐授权、肖像授权、AI 不冒充实景、口播风险高于字幕 |

### 12.4 明确不移植的东西

下面这些是朋友圈那套产品形态的产物，**视频这边一条都不用**：

| 不移植 | 为什么 |
|---|---|
| 早 / 中 / 晚三个时段 | 视频没有日更节奏，按需求出片 |
| 五段式 + emoji + 150–200 字 | 那是能慢慢读的篇幅，视频里一句字幕只停两三秒 |
| 「配文必须泛用、不许出现行业词」 | 那条是为「谁都能转发」设计的。视频是定向播放，该具体就具体 |
| 参考库轮转挑风格 | 朋友圈要防「十天一个样」。视频按类型定风格，同一类型就该长得像一家人 |
