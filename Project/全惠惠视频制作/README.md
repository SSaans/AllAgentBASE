### 0.1 一句话指令

用户日常只会丢一句话过来，比如：

## 一、六步闭环：从一句话到一条片子

### 第 1 步 · 把领导的话翻译成需求卡（限 500 字）

见第五章。**这一步不做完，后面全部不许动。**

### 第 2 步 · 定档位：这条片子值多少钱

见第八章。默认从最低档起，只有踩了升级判据才往上走。

### 第 3 步 · 文案和分镜，一次定死

- 文案按 `文案规范.md` 写，**先定稿再动画面**
- 分镜拆成 3–8 个镜头，每个镜头写清：画面内容 / 镜头运动 / 时长 / 是否含字
- 分镜清单落成 `镜头清单-v1.md`，一个镜头一行

> 这张表是省钱的命根子。后面用户说「第三个镜头换掉」，就只重出那一个镜头，其余原样复用。

### 第 4 步 · 备素材，先查有没有现成的

按顺序找，找到就停：

1. 公司既有素材 —— `260930_会议视频合集`（片头模板 8 套、大气史诗音乐、既有 logo 片尾）
2. 设计资料 —— logo 矢量原稿（`全惠惠logo(1).pdf`）
3. 都不够，才生成

### 第 5 步 · 生成（只调一次）

按第八章的路径走。**同一镜头最多试两次**，两次不成按止损条款处理，不许硬磕。

### 第 6 步 · 本地合成 + 交付

用 ffmpeg 干这些活，零 token：拼接、转场、贴 logo、上字幕、混音、压片、导出封面。

交付只交两样：**成片文件** + **一句说明**（多长、什么规格、改了哪里）。

> 不要贴文件清单，不要贴命令行，不要贴路径表。用户要的是能直接发出去的片子。

## 二、公司是干什么的，给谁看

### 2.1 业务四块

| 板块 | 一句话 |
|---|---|
| 直销 | 靠人拉人、靠信任成交，视频要经得起转发 |
| 开会讲课 | 公司的主场。会议、培训、招商、表彰，视频素材的大头 |
| 房产 | 管得最严，一句话说错就出事 |
| 购物平台 | 讲省钱、讲聚合、讲商家入驻 |

公司全名 **全惠惠**。旧名「全商汇」已经作废，见到这三个字一律按全惠惠处理（老素材文件名里还有，别照着念）。

### 2.2 受众决定一切

看片子的人，四十岁以上占大头，**董事长七十多岁**。

所以：

- **字要大。** 手机上看得清，会议室大屏上更得看得清
- **节奏别太快。** 三秒一个镜头那种剪法，四十岁往上的人跟不上，看完只记得晃
- **话说直白。** 不玩梗、不用网络流行语、不写英文缩写
- **一条片子说一件事。** 又要讲模式又要讲产品又要讲愿景，最后一样都记不住
- **气派要足。** 这一代人认「有排场」：红毯、金色、光效、鼓点、大场面。冷淡极简那套在他们眼里叫「没做完」

### 2.3 经营理念：文案的底料

核心理念八个字，一切从这儿长出来：

> **全心全意聚商机　互惠互利赢未来**

往下一层是三为方针：**为消费者省钱、为商家引流、为事业伙伴创造价值。**

完整的理念文本（5W1H 六问、品牌释义、五条价值观、新商业说明）摘录在 `文案规范.md` 第二章。写文案前读那一份。

## 四、长什么样：风格基线

### 4.1 大方向

**大企业调性**：稳、正、有分量。看完让人相信这是一家正经公司，不是微商，不是野生团队。

同时要有**宣传效果**：不能做成内部会议纪要那种平铺直叙，得让人看完想了解一下、想加入、想合作。

这两条不矛盾，办法是：**画面稳，节奏有起伏；话不多，句句有落点。**

### 4.2 既有风格：从素材里量出来的

公司此前做过会议快剪、会议记录视频，风格要接着走。已实测的硬参数（`全商汇LOGO演绎片尾.mp4`）：

| 项 | 实测值 | 结论 |
|---|---|---|
| 时长 | 11.12 秒 | **片尾就做 10–12 秒**，不要拉长 |
| 分辨率 | 1920×1080 | 1080p 是基准线 |
| 帧率 | 25 fps | 沿用 25，不要混 30 |
| 编码 | H.264 Main / yuv420p | 兼容性最好，别用 HEVC |
| 码率 | 约 14 Mbps | 成片落在这附近，太高没必要 |
| 音频 | AAC 48kHz 立体声 | 照这个来 |
| 音乐 | 大气史诗（有现成素材） | 优先复用，别重新找 |

模板库里已有的八套片头包装（蓝色玻璃、LOGO 聚合、翻页相册、党政翻页、电影放映、爆炸片头等），说明既有风格走的是**包装型片头 + 快剪 + LOGO 演绎收尾**这条路。

> ⚠️ **这段是推断，不是事实。** 上表的技术参数是实测的，内容风格是从文件名和目录结构推出来的，没有逐帧看过。执行方第一次做片时，要打开最近一届成片（`2026-10-7 215700 第26届`）目视对齐一次，把实际观察回填到本节，并把「待确认」标记去掉。

### 4.3 七条硬规则

1. **LOGO 不许由 AI 画。** logo 一律用矢量原稿叠上去。图像/视频模型画不准中文和 logo，出来的东西必须报废
2. **中文不许由 AI 画。** 字幕、标语、落版全部程序叠加。这一条跟平面设计项目同源，理由一样
3. **不碰花哨。** 无意义的光斑乱飞、故障风、快闪、鬼畜、卡通小人、荧光色，全部不许
4. **不玩梗。** 不用网络热词、不用谐音、不用「整活」
5. **一屏一句。** 同一画面上的字不超过两行，每行不超过 12 字
6. **落版必须有 logo。** 每条片子结尾都要有品牌落版，这是身份
7. **音量对齐。** 人声 -6dB 上下，音乐 -18dB 上下，不许背景音乐压过人说话

### 4.4 不碰的清单（跟平面设计项目保持一套口径）

荧光色、糖果色、卡通风、网红夸张风、一层叠一层的花哨渐变、公文简报式排版、可辨识的异地地标（公司在中山，不拿东方明珠当背景，也不把生成画面叫中山实景）。

## 五、需求怎么进来：把领导的话变成 500 字

### 5.1 为什么要有这一步

领导说「搞个大气点的视频」，这句话能派生出二十种做法，每一种都要烧钱。**不先把话捏实，后面全是返工。**

所以定了统一动作：任何口头要求，先落成一张**需求卡**，再动手。

### 5.2 需求卡：七个格子

```
【需求卡】<片子名>

1. 给谁看：
2. 看完要他干一件事：
3. 多长：
4. 必须出现：
5. 绝对不能出现：
6. 什么时候要：
7. 放哪儿播：
```

七个格子填满，**总字数不超过 500 字**。超了就砍描述、留事实。

填不出来的格子，才去问人。问也只问业务，不问技术。

### 5.3 「一岁小孩都能听懂」的四条改写法则

| 法则 | 做法 | 反例 → 改写 |
|---|---|---|
| 一句一事 | 一句话只装一个意思 | 「要体现我们的聚合赋能生态和多方共赢格局」→「讲清楚三件事：消费者省钱、商家来客、伙伴赚钱」 |
| 换成看得见的东西 | 形容词换成画面 | 「要大气」→「黑底、金字、慢推镜头、鼓点音乐」 |
| 砍掉模糊词 | 之类的、差不多、那个感觉、稍微、尽量 | 「稍微高级一点」→「去掉卡通元素，只留实拍和文字」 |
| 数字写死 | 长度、时间、数量全用数字 | 「别太长」→「60 秒以内」 |

### 5.4 一张写好的需求卡长什么样（样例）

```
【需求卡】logo 片尾动画 v1

1. 给谁看：会议大屏 + 视频号，四十岁以上为主，董事长也在看
2. 看完要他干一件事：记住「全惠惠」这个名字和那只红凤凰
3. 多长：11 秒（跟既有片尾一致）
4. 必须出现：红凤凰图形、书法体「全惠惠」、英文 QUANHUIHUI、
   核心理念「全心全意聚商机，互惠互利赢未来」
5. 绝对不能出现：AI 画歪的 logo、错字、花哨光斑、卡通元素、云纹
6. 什么时候要：明天下午
7. 放哪儿播：会议结尾大屏，也会嵌进快剪片尾

（共 168 字）
```

### 5.5 需求卡放哪

跟成片放一起：`<月日>\需求卡-<片子名>.md`。

改需求就在原卡上改，改完在下面追一行「改了什么 · 日期」，不要另建新卡。

## 六、文案：这个项目的一半活

**多数情况下，片子好不好看取决于文案。** 画面能生成，话得有人想。

文案分三种形态，各有字数硬限：

| 形态 | 用在哪 | 字数 | 规矩 |
|---|---|---|---|
| **屏上大字** | 画面上的标语 | ≤12 字/行，≤2 行 | 从口号库取，不自己编 |
| **旁白** | 配音念的 | 每句 ≤15 字，全片 ≤120 字 | 短句、动词开头、不用书面语 |
| **落版** | 结尾品牌条 | 固定 | 「全惠惠，全心全意聚商机，互惠互利赢未来。」 |

完整规范（理念底料、口号库、五段式、合规红线、反例）在 **`文案规范.md`**，动笔前必读。

三条最容易犯的错：

1. **把理念原句整段搬上屏** —— 那是给人读的，不是给人看的。上屏只留八个字
2. **旁白写成汇报材料** —— 「依托数字化工具优化传统商业链路」这种话，念出来没人听得懂
3. **编事实** —— 编数字、编案例、编客户评价，一条都不许。夸张修辞随便用，编数据是造假

## 八、怎么生成，怎么省 token

这一章是全项目最要紧的地方。用户只开了 Plus，额度有限，**烧超了会被叫停**。

### 8.1 三条路，按价钱从低到高

| 档 | 路径 | 花什么 | 什么时候用 |
|---|---|---|---|
| **L1** | 只交提示词包 + 分镜 + 文案，不生成 | 几乎为零 | 用户只要方案；或片子复杂到该由人拿去专业软件做 |
| **L2** | seedream 直出：一句提示词 / 一张参考图 → 一段视频 | 低 | 单个镜头、无中文字、无 logo、画面简单 |
| **L3** | GPT 当 agent 跑全流程（能读流程文件、自己编排） | 高 | 多镜头、要叙事、要一致性 |
| **L2.5** | 混合流：执行方出提示词 + 关键帧，seedream 补间成片 | 中 | **默认推荐**，尤其片尾动画 |

**默认从 L2.5 起。** 只有 L2.5 搞不定才升 L3，只有用户只要方案才降 L1。

### 8.2 混合流怎么走（重点，省钱的核心）

```
① 定 3–5 个关键帧（首帧、转场帧、尾帧）
   → 出图，或用既有素材裁帧
② 每一段交给视频模型：首帧图 + 尾帧图 + 一句运动描述
   → 模型只管「怎么动」，不管「画什么」
③ 本地拼接 + 贴 logo + 上字幕 + 混音
   → ffmpeg，零 token
```

为什么省钱：**首尾帧锚定之后，画面内容被钉死了**，模型没有自由发挥的空间，一次过的概率大幅上升。模型乱编的根源就是「只给一句话让它自己想象」。

一句话的运动描述长这样：

> 镜头缓慢推近，金色光尘从左向右飘过，凤凰图形由暗转亮

不要写「让它看起来很有气势」——模型不知道什么叫有气势。

### 8.3 怎么让缓存命中（这是省钱的最大杠杆）

缓存计费只看一件事：**这次请求的开头，跟上次是不是逐字节一样。**

命中不了，通常就三个原因：换了措辞、调了顺序、加了新东西在前头。

**五条纪律：**

1. **固定包原样复制，一个字不改。** 系统包（`提示词库.md` 里的 S 段）每次都整段贴，不许顺手润色、不许改标点、不许调顺序
2. **顺序永远一样。** `S 段（系统包）→ C 段（公司常量：理念、口号、风格）→ T 段（本次任务变量）`。新的东西只能加在最后
3. **一批活连着干，别开新会话。** 缓存有存活时间，断太久就白攒了。同一天的多条片子排在一起做
4. **别在中途升级流程文件。** 发现要改，先记下来，等这一批交完再改，改完在 `CHANGELOG.md` 写一行
5. **少读文件。** 这一轮读过的规范就记住，不要每做一个镜头回去翻一遍

> 🔴 追加一个镜头、改一句文案，就只在 T 段改那一行，前面的 S 段和 C 段原样不动。这样改一次只花一点点。

### 8.4 一次过的六条纪律

1. 文案定稿才开生成
2. 分镜表填满才开生成（每个镜头都有画面、运动、时长）
3. 每个镜头先出**静帧**确认，静帧不对不出视频
4. 不在生成中途改提示词，改就整段重来
5. 一个镜头最多两次，两次不成换档或换思路
6. 不主动多做一版让人挑

### 8.5 止损条款

| 情况 | 处理 |
|---|---|
| 同一镜头两次不成 | 停手，换路径（L3 降 L2.5 或反之），并在交付说明里讲清楚卡在哪 |
| 换了路径还不成 | 交 L1（只交提示词 + 分镜），说明「这条需要人拿专业软件收尾」 |
| 用户说「太烧了」 | 立刻停，回到 L1，把已生成的东西整理成可复用资产 |
| 用户说「别搞了」 | 立刻停手，只交当下点名那一件 |

**不许为了「看起来努力」硬磕。** 磕出来的片子不合格，钱也白花了。

### 8.6 本地合成：零 token 的活都在这儿

ffmpeg 在这台机器上：

```
C:\Users\Unbox\AppData\Roaming\LottieViewConvert\ffmpeg\ffmpeg.exe
```

（只有 ffmpeg，没有 ffprobe。查视频参数用 `ffmpeg -i 文件 -f null -`，看 stderr。）

常干的活：

| 活 | 一句话 |
|---|---|
| 查参数 | `ffmpeg -i 片子.mp4 -f null -`，看 Duration 和 Stream |
| 拼接 | concat demuxer，同规格文件直接拼，不重编码 |

> 这些命令写在 `提示词库.md` 末尾的「本地合成命令条」里，直接抄，不用现查。

## 九、命名与版本：v1、v2 怎么排

### 9.1 成品放哪

```
E:\260930_全惠惠工作合集\261017_视频制作合集\
├── 10月17日\
│   ├── 10月17日-片尾logo-v1.mp4
│   ├── 10月17日-片尾logo-v1-封面.jpg
│   ├── 10月17日-片尾logo-镜头清单-v1.md
│   └── 需求卡-片尾logo.md
└── 10月18日\
    └── ...
```

- 每天一个文件夹，日期写法固定「10月17日」，不写 20261017
- 当天所有产出都进当天文件夹
- **别的日期的文件夹一个字都不动**

### 9.2 版本号规则（跟平面设计项目同一套）

| 情况 | 版本号 |
|---|---|
| 同一天改稿 | 读出当天最大 `vN`，本次 `v(N+1)` |
| 新的一天 | 从 `v1` 起，不接着前一天加 |
| 文件夹是空的 | 从 `v1` 起 |

版本号是「这一天改了几稿」，不是「总共出了几版」。跨天归零。

### 9.3 视频的版本跟平面图有一处关键不同

**平面图改稿要整张重出。视频不用。**

改局部的时候，只重出受影响的镜头，其他镜头直接从上一版复用。所以：

- 候选镜头分开放：`10月17日\片段\片尾-v1\s01.mp4`、`s02.mp4`……
- 最终成片才拼起来
- 出新版时，**只换掉变了的那个片段文件**，再拼一次（拼接零 token）

这样 v1 → v2 只改一个字幕位置，成本几乎为零。

### 9.4 镜头清单：视频项目的核心资产

每个片子配一份 `镜头清单-vN.md`：

| 镜头 | 时长 | 画面 | 运动 | 屏上文字 | 提示词文件 | 状态 |
|---|---|---|---|---|---|---|
| s01 | 2.5s | 黑底，一点金光亮起 | 光点扩散 | — | `p-s01.txt` | ✅ v1 采用 |
| s02 | 3.0s | 凤凰轮廓由暗转亮 | 缓慢推近 | — | `p-s02.txt` | ✅ v1 采用 |
| s03 | 3.5s | 书法字逐个落定 | 静止 | 全惠惠 | — | 程序叠加 |

**改稿时只改这张表的一行，重出那一个镜头。** 这张表同时也是复盘材料：哪个镜头返工多，下次就在提示词上提前防。

## 十一、给 Agent 的话

### 11.1 文件索引

| 文件 | 干什么用 | 什么时候读 |
|---|---|---|
| `README.md` | 项目基座。定位、风格、流程、命名、省钱 | **每次开工前读一遍**（就是本文件） |
| `BRD.md` | 需求真相来源 + 验收标准 + 风险 | 接新类型、做验收、需求有争议时 |
| `Task.md` | 任务清单 | 开工前看，收工后更新 |
| `CHANGELOG.md` | 本项目日志，最近 15 条 | 开工前读最近 3 条 |
| `文案规范.md` | 理念底料 + 口号库 + 三种文案形态 + 合规红线 | **写任何文案前必读** |
| `提示词库.md` | 系统包（S 段）、各类型提示词骨架、本地合成命令 | 开生成前读对应那一节 |

### 11.2 开工三步（先报后动）

1. 读规范：本文件 + `文案规范.md` 对应章节 + 最近 3 条 CHANGELOG
2. 报方案：一句话说清「走哪档、几镜头、多长、文案大概讲什么」，等用户点头
3. 拿到「开工」两个字才动手

### 11.3 收工四段话

```
① 任务号：
② 改动/产出：交了什么文件，多长、什么规格
③ 自测证据：时长/分辨率/帧率核过，logo 没变形，字幕无错字
④ 遗留与待决策：卡在哪、下一步建议
```

**自测不等于验收。** 交完写「待复验」。

### 11.4 一句话交件

交完只说一句，比如：

> 「片尾 v1 出了，11 秒 1080p，logo 和理念落版都在，已放到位。」

不贴清单、不贴路径表、不贴命令。

## 十三、这件事为什么值得做厚规划

视频贵。一条 30 秒的片子，如果返工三次，烧掉的额度够出三百张平面图。

所以本项目的规划做得比平面设计厚：需求卡、档位表、首尾帧法、缓存纪律、止损条款、镜头级版本。这些不是流程洁癖，**每一条都对应一次真实的烧钱方式**。

规划写厚了，执行就能薄。这是这个项目唯一的经济学。
