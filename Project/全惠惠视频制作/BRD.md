## 一、项目定位

### 1.1 一句话

给全惠惠提供**能直接对外播**的视频产出能力，覆盖会议、品牌、业务三条线。

### 1.2 这个项目解决什么问题

公司现在的视频活是零散找人做的：一场会剪一条，要个片头再找一次。结果有三个：换个人就换个风格，改一稿就算一次钱，领导今天说隔几天才看到东西。

本项目把这摊事变成固定流程：风格有个准头，成本有本账，交付有个节奏。

### 1.3 角色定位（关键，容易搞错）

| 项 | 内容 |
|---|---|
| 仓库里的角色名 | **开发 Agent** |
| 实际干的活 | **执行**：直接出视频、出提示词、出策划案 |
| 明确不干的活 | 不写功能代码、不开发软件、不搭服务、不改别的项目 |

> 角色名沿用仓库既有约定（规划 / 开发 / 测试三档），不改名。但「开发」在本项目里的含义是「把东西做出来」，不是「写程序」。

## 五、功能需求

### FR-1 需求转化

**输入**：领导的任意一句话。
**输出**：一张需求卡，七格填满，≤500 字。
**规则**：
- 七格：给谁看 / 看完干什么 / 多长 / 必须出现 / 绝不能出现 / 什么时候要 / 放哪儿播
- 改写按四条法则（`README.md` §5.3）：一句一事、换成看得见的、砍模糊词、数字写死
- 超过 500 字必须砍，**不许超**
- 只有在业务信息缺失时才问人，技术细节自己定

**验收**：拿需求卡给一个没参与过的同事看，他能说出「这条片子要干什么」。

### FR-2 文案撰写

**输入**：需求卡 + 经营理念。
**输出**：三种形态的文案，各守字数。

| 形态 | 字数硬限 | 判据 |
|---|---|---|
| 屏上大字 | ≤12 字/行、≤2 行 | 站在三米外能一眼读完 |
| 旁白 | 每句 ≤15 字、全片 ≤120 字 | 念出来不打结 |
| 落版 | 固定句 | 「全惠惠，全心全意聚商机，互惠互利赢未来。」 |

**规则**：
- 标语只能从口号库取或按「转译三步」变，不自己编（见 `README.md` §6.4、§6.5）
- 夸张修辞可以，编数据不行
- 过合规词表（§九）

### FR-3 分镜设计

**输出**：`镜头清单-vN.md`，一行一个镜头，含：镜头号 / 时长 / 画面 / 运动 / 屏上文字 / 提示词文件 / 状态。

**规则**：
- 3–8 个镜头。太少撑不起叙事，太多四十岁以上的人跟不上
- 每个镜头的画面必须写成人能画出来的样子（「黑底，一点金光亮起」），不写抽象词
- 有字、有 logo 的镜头，单独标出这一层怎么处理

**验收**：照镜头清单能不看原片复现整条片子。

### FR-4 画面生成

三档：

| 档 | 干什么 | 什么时候用 |
|---|---|---|
| L1 | 只交提示词、分镜、文案 | 用户只要方案，或这活得拿专业软件做 |
| L2 | 一句提示词或一张参考图，出一段 | 试单镜头，看画面长什么样 |
| L3 | GPT 当 agent 读流程自己编排，出整条 | 默认，简单的也走这条 |

规则：
- 能锚关键帧就锚，别只给一句话让模型自己想
- 画面里的字越少越好，logo 用参考图带过去
- 同一镜头最多两次

### FR-5 拼接与配乐

各段在其他工具里生成好，拼成整条，配乐配声。

规则：
- 输出规格照 §4.2
- 音乐优先用生成的，用现成的要有授权
- 音效跟着画面走，别铺满

**验收**：文件能直接拖进微信或视频号播放，不报错。

### FR-6 归档与迭代

**目录**：`E:\260930_全惠惠工作合集\261017_视频制作合集\<月日>\`
**命名**：`<月日>-<类型短名>-v<N>.mp4`
**版本**：跟日期绑，跨天归零
**改局部**：只重出受影响的镜头，其余沿用上一版，重新拼一次

### FR-7 类型扩展

新增类型只需三样：类型卡（进 `提示词库.md`）、命名规则（沿用）、验收清单（按类型补 2–3 条专属项）。

**验收**：加 T09 类型时，`README.md` 与 `BRD.md` 只需在登记表加一行，其余不动。

## 七、技术方案要点

### 7.1 为什么用关键帧打底

只给一句话让模型生成，它自己发挥，画面不可控，改一处全片变，返工就是烧钱。

先出首帧和尾帧，再让模型补中间。内容被图片钉住，模型只剩运动要管，出错的面小了，一次过的机会就大。

### 7.2 logo 和字怎么处理

模型画不准中文和矢量标志，这是模型能力的边界，提示词调不好。

实际做法：logo 优先当参考图喂进去，让它在原图基础上动。画面上必须出现的字，越少越好，一行说一件事。动态里一闪而过的画面，轻微偏差看不出来；要做静止定格的大落版，宁可画面简单，别硬抠细节。

### 7.3 为什么缓存策略写进流程

缓存命中与否，差价好几倍。命中条件只有一条：请求开头逐字节一致。所以不改措辞、不调顺序、不中途改文件，这是计费规则要求的。

### 7.4 不做本地剪辑

执行方不碰命令行，不装工具，不做本地剪辑加工。拼接在其他生成工具里完成。用命令行加工视频，一是容易出错，二是跟「纯生成」这条链路拧着，出了问题也没人接得住。

## 九、合规红线

视频比图文更严：一句话说错，传播出去收不回来。

| # | 红线 | 具体 |
|---|---|---|
| 1 | 不承诺收益 | 不用「稳赚」「保本」「零风险」「一定能赚」「躺赚」 |
| 2 | 不用绝对化用语 | 不用「最」「第一」「唯一」「国家级」「顶级」 |
| 3 | 不编数据 | 不编业绩、不编人数、不编案例、不编客户评价 |
| 4 | 消费权益口径照原文 | 权益仅限本人后续消费抵扣使用，**不可提现、不可变现、不可转让** |
| 5 | 房产不承诺升值 | 不做投资回报表述，不说「必涨」「翻倍」 |
| 6 | 直销表述谨慎 | 不描述「拉人头获利」，只讲推广服务佣金按有效成交计算 |
| 7 | 不做功效暗示 | 大健康类产品不做医疗、保健功效表述 |
| 8 | 不用未授权素材 | 音乐、字体、影像都要可商用；人物出镜要授权 |
| 9 | AI 画面不冒充实景 | 生成画面不许说成「我们在中山的实拍」 |

> 落地要求：把上表做成可扫的词表，文案定稿前扫一遍，命中就拦。词表见 `README.md` §6.7。

## 十、风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 领导需求含糊，做出来不对 | 整条返工，最贵 | 需求卡七格闸门，填不满不开工 |
| 模型生成不稳定 | 反复重试烧额度 | 首尾帧锚定 + 单镜头 2 次止损 |
| 中文字或 logo 让模型硬画 | 出来一定是歪的 | 字越少越好，logo 用参考图带过去 |
| 风格跑偏 | 一次比一次不像公司 | 每次开工先看几条大牌 logo 动画，定个准头 |
| 缓存老是打不中 | 成本翻几倍 | S/C/T 固定顺序 + 不改措辞 + 同批连做 |
| 越界改了别的项目 | 违反用户红线 | `git status` 收工自查，只允许本项目路径有改动 |
| 素材版权出问题 | 下架、纠纷 | 只用授权/免版权素材，成品不进公开仓库 |
