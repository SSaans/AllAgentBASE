## 一、项目定位

### 1.1 一句话

给全惠惠提供**能直接对外播**的视频产出能力，覆盖会议、品牌、业务三条线。

### 1.2 这个项目解决什么问题

公司现在的视频活是零散找人做的：一场会剪一条、要个片头再找一次。三个后果：

1. **风格不统一** —— 每次换人，每次一个样
2. **成本不可控** —— 按条计价，改一稿再算一次钱
3. **速度慢** —— 领导今天说，隔几天才看到东西

本项目要把这三件事变成可重复的流程：风格有一套基线、成本有一本账、交付有一个固定节奏。

### 1.3 角色定位（关键，容易搞错）

| 项 | 内容 |
|---|---|
| 仓库里的角色名 | **开发 Agent** |
| 实际干的活 | **执行**：直接出视频、出提示词、出策划案 |
| 明确不干的活 | 不写功能代码、不开发软件、不搭服务、不改别的项目 |

> 角色名沿用仓库既有约定（规划 / 开发 / 测试三档），不改名。但「开发」在本项目里的含义是「把东西做出来」，不是「写程序」。

## 五、功能需求

### FR-1 需求转化

**输入**：领导的任意一句话。
**输出**：一张需求卡，七格填满，≤500 字。
**规则**：
- 七格：给谁看 / 看完干什么 / 多长 / 必须出现 / 绝不能出现 / 什么时候要 / 放哪儿播
- 改写按四条法则（`README.md` §5.3）：一句一事、换成看得见的、砍模糊词、数字写死
- 超过 500 字必须砍，**不许超**
- 只有在业务信息缺失时才问人，技术细节自己定

**验收**：拿需求卡给一个没参与过的同事看，他能说出「这条片子要干什么」。

### FR-2 文案撰写

**输入**：需求卡 + 经营理念。
**输出**：三种形态的文案，各守字数。

| 形态 | 字数硬限 | 判据 |
|---|---|---|
| 屏上大字 | ≤12 字/行、≤2 行 | 站在三米外能一眼读完 |
| 旁白 | 每句 ≤15 字、全片 ≤120 字 | 念出来不打结 |
| 落版 | 固定句 | 「全惠惠，全心全意聚商机，互惠互利赢未来。」 |

**规则**：
- 标语只能从口号库取或按洗稿规则变，不自己编（见 `文案规范.md` §三）
- 夸张修辞可以，编数据不行
- 过合规词表（§九）

### FR-3 分镜设计

**输出**：`镜头清单-vN.md`，一行一个镜头，含：镜头号 / 时长 / 画面 / 运动 / 屏上文字 / 提示词文件 / 状态。

**规则**：
- 3–8 个镜头。少于 3 个撑不起叙事，多于 8 个四十岁以上的人跟不上
- 每个镜头的画面必须写成人能画出来的样子（「黑底，一点金光亮起」），不写抽象词
- 含中文字、含 logo 的镜头，文字层标注为「程序叠加」

**验收**：照镜头清单能不看原片复现整条片子。

### FR-4 画面生成

三档路径，按成本从低到高：

| 档 | 路径 | 适用 | 升级判据 |
|---|---|---|---|
| L1 | 只交提示词 + 分镜 | 用户只要方案；或复杂到该人工收尾 | — |
| L2 | seedream 直出（提示词 / 单张参考图） | 单镜头、无字、无 logo | 一次不成不升级，换提示词重试一次 |
| L2.5 | 混合流：执行方出关键帧 + 运动描述，模型补间 | **默认** | 关键帧出不来，或镜头需要连续运镜时升 L3 |
| L3 | GPT agent 读流程文件自行编排 | 多镜头叙事、要求一致性 | — |

**硬规则**：
- 中文与 logo 一律程序叠加，**不让模型画**
- 首尾帧锚定优先：能锚帧就不裸给一句话
- 同一镜头最多两次

### FR-5 本地合成

用 ffmpeg 完成：拼接、转场、贴 logo、上字幕、混音、压片、导封面。

**规则**：
- 人声 -6 dB、音乐 -18 dB，音乐不许压过人声
- 转场克制：切、叠化为主，不用花哨转场
- 输出规格照 §4.2

**验收**：文件能直接拖进微信/视频号播放，不转码、不报错。

### FR-6 归档与迭代

**目录**：`E:\260930_全惠惠工作合集\261017_视频制作合集\<月日>\`
**命名**：`<月日>-<类型短名>-v<N>.mp4`
**版本**：跟日期绑，跨天归零
**改局部**：只重出受影响镜头，其余复用上一版片段，重新拼接（零 token）

### FR-7 类型扩展

新增类型只需三样：类型卡（进 `提示词库.md`）、命名规则（沿用）、验收清单（按类型补 2–3 条专属项）。

**验收**：加 T09 类型时，`README.md` 与 `BRD.md` 只需在登记表加一行，其余不动。

## 七、技术方案要点

### 7.1 为什么以混合流为主

纯提示词生成的问题：模型自由发挥，画面内容不可控，改一处全片变。返工率高，返工就是烧钱。

首尾帧锚定把「内容」和「运动」拆开：内容由执行方定（出帧），运动交给模型（补间）。模型出错的空间被压缩到只剩运动本身，一次过率显著上升。

### 7.2 为什么 logo 必须程序叠加

图像/视频模型画不准中文，画不准矢量 logo。这是模型能力边界，不是提示词问题。平面设计项目在 10 月 12 日已经踩过这个坑并写进规范，本项目直接继承。

### 7.3 为什么缓存策略要写进流程

缓存命中与否，差价在数倍。命中条件只有一个：**请求前缀逐字节一致**。所以「不改措辞、不调顺序、不中途改文件」不是洁癖，是计费规则。

### 7.4 ffmpeg 位置

```
C:\Users\Unbox\AppData\Roaming\LottieViewConvert\ffmpeg\ffmpeg.exe
```

本机只有 `ffmpeg.exe`，没有 `ffprobe`。查参数用 `ffmpeg -i <file> -f null -`，读 stderr。

## 九、合规红线

视频比图文更严：一句话说错，传播出去收不回来。

| # | 红线 | 具体 |
|---|---|---|
| 1 | 不承诺收益 | 不用「稳赚」「保本」「零风险」「一定能赚」「躺赚」 |
| 2 | 不用绝对化用语 | 不用「最」「第一」「唯一」「国家级」「顶级」 |
| 3 | 不编数据 | 不编业绩、不编人数、不编案例、不编客户评价 |
| 4 | 消费权益口径照原文 | 权益仅限本人后续消费抵扣使用，**不可提现、不可变现、不可转让** |
| 5 | 房产不承诺升值 | 不做投资回报表述，不说「必涨」「翻倍」 |
| 6 | 直销表述谨慎 | 不描述「拉人头获利」，只讲推广服务佣金按有效成交计算 |
| 7 | 不做功效暗示 | 大健康类产品不做医疗、保健功效表述 |
| 8 | 不用未授权素材 | 音乐、字体、影像都要可商用；人物出镜要授权 |
| 9 | AI 画面不冒充实景 | 生成画面不许说成「我们在中山的实拍」 |

> 落地要求：把上表做成可扫的词表，文案定稿前扫一遍，命中就拦。词表放 `文案规范.md` §六。

## 十、风险与对策

| 风险 | 后果 | 对策 |
|---|---|---|
| 领导需求含糊，做出来不对 | 整条返工，最贵 | 需求卡七格闸门，填不满不开工 |
| 模型生成不稳定 | 反复重试烧额度 | 首尾帧锚定 + 单镜头 2 次止损 |
| 中文字/logo 由模型画 | 成品必须报废 | 硬规则：一律程序叠加 |
| 风格跑偏 | 一次比一次不像公司 | 风格基线 + 每次对齐最近一届成片 |
| 缓存老是打不中 | 成本翻几倍 | S/C/T 固定顺序 + 不改措辞 + 同批连做 |
| 越界改了别的项目 | 违反用户红线 | `git status` 收工自查，只允许本项目路径有改动 |
| 素材版权出问题 | 下架、纠纷 | 只用授权/免版权素材，成品不进公开仓库 |
