# 提案

## Why

桌宠装好后一直有个说不清的地方：什么时候它会自己动、什么时候必须停。BRD 里事故复盘和验收场景混在一起，再加上「专注监督」这条迭代需求，很难判断某个行为是设计如此还是出了毛病。

## What Changes

拆成三个能力，每条配场景。事故复盘留在 README 与历史文件里。

- 桌宠运行：启动、常驻、退出
- 专注监督：定时看屏幕，到点提醒
- 停止边界：什么情况下必须闭嘴、必须停

## Capabilities

### New Capabilities

- `桌宠运行`: 启动后常驻、单实例、退出干净
- `专注监督`: 到点识屏、按设定提醒
- `停止边界`: 用户忙、退出、重启后的行为

### Modified Capabilities

无，首次建立基线。

## Impact

- `BRD.md` 退役，行为进 `openspec/specs/`
- 桌宠本体与运行目录不动，只改仓库内文档
