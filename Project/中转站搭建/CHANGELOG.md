## [2026-09-22] 规划 Agent — 立项：搭 new-api 面板聚合上游中转站（规划完成，待用户提供坐标）

**背景**：用户先让另一 Agent 调研了「sub2api 面板中转站」（22 站横向对比），随后指派规划 Agent「新建 sub2api 中转站搭建 project 并作出详细规划」。

**本轮澄清（关键，避免立项立歪）**：经与用户确认，真实需求是——**在本机 Windows 上搭一个 new-api 面板，把自己在用的别家中转站接到上游，先自用**。原表述里的「sub2api」是调研对象（22 家站的底座），**不是**用户要装的东西。

**① 选型结论：底座用 new-api（BRD §二）**
- 本项目上游 = 别家中转站的 API Key → new-api 的渠道管理正是为此设计
- sub2api 的主场是「订阅账号池 + 拼车分发」，用户手上**无任何 AI 账号**，用它等于放弃其唯一长处
- sub2api 未废弃，转为**延期方案**（BRD §六 6.7）：等有订阅账号时再单独立项

**② 调研报告的定位（BRD §三）**
定位为**上游选站参考**，不是搭建文档。三条可复用价值：候选上游清单、面板识别方法（`.well-known/ai-transit.json` / 快照接口 / `x-new-api-version` 头）、价格与渠道基线（0.02x–0.5x、1 元=1 美元、逆向渠道风险）。
