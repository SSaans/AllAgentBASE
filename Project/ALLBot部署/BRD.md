## 项目目标

把已经能正常聊天的 AstrBot QQ 机器人（人设「丛雨」）调教成想要的样子，一共三件事：

1. **插件命令能正常用**——群里发 `/分析设置`、`/群分析`、`/群漫画` 这类指令，插件要真的响应。

3. **长回复走转发卡片**——话短就直接发；话太长（超过设定的字数）就打包成 QQ「合并转发聊天记录」卡片发出去。

## 核心功能与技术方案

### 功能 1：插件命令正常调用（已达成）

**为什么以前 `/` 命令没反应**：命令过滤器 `astrbot/core/star/filter/command.py:191-192` **第一行就要求** `event.is_at_or_wake_command` 为真，否则直接 `return False`——命令不触发，连报错都没有。这个标志只在三种情况下为真（`pipeline/waking_check/stage.py:102-148`）：① 消息以 `wake_prefix` 里某个词开头；② @ 了机器人 / @全体 / 引用机器人的消息；③ 私聊。

**正确用法**：**@丛雨 + 指令**。不要靠往 `wake_prefix` 里塞 `/`——实测那样做会让群里所有 `/` 开头的消息都被当成唤醒，跟别的 bot 指令打架。

插件指令：`/群分析`、`/群漫画`、`/分析设置`、`/设置格式`、`/设置模板`、`/查看模板`、`/增量状态`。

### 功能 2：群总结（只靠指令触发，已达成）

用现成插件 `astrbot_plugin_qq_group_daily_analysis`：

- `/群分析` 出报告（话题 ≤5、成员称号 + MBTI ≤8 人、金句 ≤5、质量锐评），格式 `image + text + html`。
- `/群漫画` 出多格漫画。
- 人设要继承丛雨：`analysis_features.keep_original_persona = **true**`（设成 false 会返回 None、人设根本不加载，这是老 Bug 的根因）；`use_plugin_specific_persona = false`。
- `llm.llm_provider_id = ""` 会自动回退到当前会话模型，**不用写死**。
- `min_messages_threshold = 200` **只管定时分析**，手动发 `/群分析` 不受限。
- 定时自动分析**不启用**（用户明确要求保持关闭）。

### 功能 3：长回复走转发卡片（已达成）

**机制**：非流式回复里，所有 Plain 文本加起来**超过** `forward_threshold` 就转成 QQ 合并转发卡片（判断在 `pipeline/result_decorate/stage.py:414`：`if word_cnt > self.forward_threshold`）。**刚好等于阈值还是直发**，多一个字才转。

**前提**：QQ 档 `provider_settings.streaming_response` 必须是 `false`，否则流式结果会提前发出去、跳过这个判断。

**4.11 群漫画看不清字——待开发调优（任务 25）**

**为什么糊（有硬证据，不是猜）**：
1. 格数 = 话题数。`comic_analyzer.py:12` 的 prompt 规定「一个话题画一格」，格数取自 `analysis_features.max_topics` = **5**。
2. 出图实测只有 **1672×940**（6 张全一样）。请求的是 1792×1008（`image_size="auto"` 经 `drawing_client.py:281-282` 解析），**上游返回时缩水了**。
3. 两条一叠加：1672×940 里塞 5 格，每格宽才 ~334 像素，还得塞气泡台词和 30 字字幕 → 必然糊；QQ 再压一次更糊。

**调优处方（按效果排序，都能在 WebUI 改完热生效）**：
1. **`analysis_features.max_topics` 5 → 2 或 3**（最有效）。⚠️ 副作用：群分析报告的话题数会一起变少（同一个开关）。
2. **`image_size` 从 `auto` 改 `2k`（2560×1440）或 `1536x1024`** ——**必须实测上游是否真按这个尺寸返回**。
3. **`aspect_ratio` 从 `16:9` 改 `4:3` 或 `1:1`**（横排每格太窄）。
4. 底部字幕从 30 字压到 12 字内（属插件 prompt 改动）。
5. 验收时**必须用 QQ「查看原图」**看，别把 QQ 压缩当成插件的锅。

**4.13 关键词自动回复插件（**不用唤醒**）——待开发（任务 27）**

> 用户原话：「这玩意儿还必须要先唤醒？你 AstrBot 插件做不到我是不信的」。**用户说得对，不用唤醒。**

- **官方就支持**：`astrbot/core/star/filter/regex.py:9` 的注释原文——「**正则表达式过滤器不会受到 wake_prefix 的制约**」。用 `@filter.regex(...)` 注册的处理器，**消息一匹配就触发，不需要 @、不需要唤醒词**（注册入口 `core/star/register/star_handler.py:297-309`）。
- ⚠️ **必须记住的坑**：filter 通过之后，这条消息会被当成「已唤醒」，**LLM 阶段照样会回复**。所以插件回完话**一定要 `event.stop_event()`**，不然她会答两遍（插件一条 + LLM 一条）。
- **要做成什么**：
  1. **一条规则 = 一个触发词 + 一组回复**。例：触发「我是笨蛋吗」→ 回复候选 `是` / `不是` / `不知道` / `钝角`，**随机挑一个**发。
  2. 回复模式**二选一**：**随机**（从候选里随便挑）或**固定**（永远只回同一条）。
  3. **白名单专属规则**：可以指定某个 QQ 号（或某个群）问同一句话时**只走固定回复**。例：某人问「我是笨蛋吗」→ **只能**回「是」。没被指定的按默认规则（随机）。
  4. **全部可编辑**：触发词、回复列表、模式、白名单，都在 WebUI 插件配置里改，保存即生效。
  5. **支持多条规则共存**。
  6. **不要注册成 `/` 命令**（那样又变回依赖唤醒前缀）。
- 配置：`_conf_schema.json`。官方插件开发文档：`https://docs.astrbot.app/dev/star/plugin-new.html`
- **去向：交开发 Agent（任务 27）**

**4.14 入群欢迎插件——待开发（任务 28）**

- **要的效果**：有人进群 → 机器人自动欢迎一句。**欢迎词可编辑**。
- **技术事实**：OneBot 的 `notice` 事件（`notice_type = "group_increase"`）会被适配器转成消息事件——`aiocqhttp_platform_adapter.py:168-196`（`_convert_handle_notice_event`）：`type` 设为 `GROUP_MESSAGE`、`message_str` 为空串、**原始事件完整保留在 `raw_message`**（里面有 `notice_type` 和新成员的 `user_id`）。
- **写法**：用 `@filter.custom_filter(自定义过滤器类)`（`astrbot/api/event/filter/__init__.py` 暴露了 `custom_filter`；基类是 `astrbot.core.star.filter.custom_filter.CustomFilter`，重写它的 `filter()`），**只在 `raw_message["notice_type"] == "group_increase"` 时通过**。
- 🔴 **最大的坑**：**绝对不能**用无条件的 `event_message_type(GROUP_MESSAGE)` 当过滤器——那样**每一条群消息**都会让 filter 通过、被当成「已唤醒」，**群里每句话都会被 LLM 回一遍**（刷屏 + 烧 token）。必须用自定义过滤器把条件卡死在「只有入群通知」。
- **可编辑项**：欢迎词（支持 `{nickname}`、`{user_id}` 这类占位符，具体由开发定）、是否 @ 新成员、开关、是否分群定制、欢迎词可否多套随机。全部 `_conf_schema.json`。
- **去向：交开发 Agent（任务 28）**

**4.15 「使用说明」插件（介绍这个 bot 能干什么）——待开发（任务 29）**

- **要的效果**：`@丛雨 使用说明`（或直接说「丛雨 使用说明」）→ 弹出一段介绍这个 bot 能干哪些事的话。**用一岁小孩也看得懂的大白话**。
- **形式**：**就是一段话**（用户明确：不要海报/图片）。
- **内容可编辑**：`_conf_schema.json` 里一个多行文本框放介绍正文，保存即生效。
- **也能让 AI 写**：插件可调用当前会话的 LLM 生成一版介绍草稿（AstrBot 标准接口 `self.context.get_using_provider().text_chat(...)`），把草稿发出来给用户看，**由用户决定是否采用**（不要自动覆盖用户写好的内容）。
- **触发**：建议用 `@filter.regex`（匹配「使用说明 / 帮助 / 能干什么 / 会什么」等词），这样**@ 或者不 @ 都能触发**；用 `filter.command` 也行但那样必须唤醒。同样记得 `event.stop_event()`。
- **去向：交开发 Agent（任务 29）**
