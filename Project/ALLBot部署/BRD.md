## 项目目标

把已经能正常聊天的 AstrBot QQ 机器人（人设「丛雨」）调教成想要的样子，一共三件事：

1. **插件命令能正常用**——群里发 `/分析设置`、`/群分析`、`/群漫画` 这类指令，插件要真的响应。
2. **群总结靠指令触发**——发指令就出当天的群聊总结（话题 / 成员称号 / 金句 / 锐评），用丛雨的口气写。
3. **长回复走转发卡片**——话短就直接发；话太长（超过设定的字数）就打包成 QQ「合并转发聊天记录」卡片发出去。

后来又陆续加了一批小功能（存图、吾辈在、卡片标题、禁言、关键词回复、入群欢迎、使用说明等），规格都写在本文档第四节。

## 核心功能与技术方案

### 功能 1：插件命令正常调用（已达成）

**为什么以前 `/` 命令没反应**：命令过滤器 `astrbot/core/star/filter/command.py:191-192` **第一行就要求** `event.is_at_or_wake_command` 为真，否则直接 `return False`——命令不触发，连报错都没有。这个标志只在三种情况下为真（`pipeline/waking_check/stage.py:102-148`）：① 消息以 `wake_prefix` 里某个词开头；② @ 了机器人 / @全体 / 引用机器人的消息；③ 私聊。

**正确用法**：**@丛雨 + 不带 `/` 的指令正文**，例如 `@丛雨 sid`、`@丛雨 群分析`、`@丛雨 群漫画`。技术勘误（2026-09-16）：当前前缀不含 `/`，@ 唤醒后核心不会额外剥掉正文的 `/`；这些命令也没有带 `/` 的别名。不要靠往 `wake_prefix` 里塞 `/`——实测那样做会让群里所有 `/` 开头的消息都被当成唤醒，跟别的 bot 指令打架。

插件指令：`/群分析`、`/群漫画`、`/分析设置`、`/设置格式`、`/设置模板`、`/查看模板`、`/增量状态`。

### 功能 2：群总结（只靠指令触发，已达成）

用现成插件 `astrbot_plugin_qq_group_daily_analysis`：

- `/群分析` 出报告（话题 ≤5、成员称号 + MBTI ≤8 人、金句 ≤5、质量锐评），格式 `image + text + html`。
- `/群漫画` 出多格漫画。
- 人设要继承丛雨：`analysis_features.keep_original_persona = **true**`（设成 false 会返回 None、人设根本不加载，这是老 Bug 的根因）；`use_plugin_specific_persona = false`。
- `llm.llm_provider_id = ""` 会自动回退到当前会话模型，**不用写死**。
- `min_messages_threshold = 200` **只管定时分析**，手动发 `/群分析` 不受限。
- 定时自动分析**不启用**（用户明确要求保持关闭）。

### 功能 3：长回复走转发卡片（已达成）

**机制**：非流式回复里，所有 Plain 文本加起来**超过** `forward_threshold` 就转成 QQ 合并转发卡片（判断在 `pipeline/result_decorate/stage.py:414`：`if word_cnt > self.forward_threshold`）。**刚好等于阈值还是直发**，多一个字才转。

**前提**：QQ 档 `provider_settings.streaming_response` 必须是 `false`，否则流式结果会提前发出去、跳过这个判断。

- 技术要点：遍历消息里**所有** Image 组件逐个下载；要处理「部分成功」的计数和话术。

**4.11 群漫画看不清字——待开发调优（任务 25）**

**为什么糊（有硬证据，不是猜）**：
1. 格数 = 话题数。`comic_analyzer.py:12` 的 prompt 规定「一个话题画一格」，格数取自 `analysis_features.max_topics` = **5**。
2. 出图实测只有 **1672×940**（6 张全一样）。请求的是 1792×1008（`image_size="auto"` 经 `drawing_client.py:281-282` 解析），**上游返回时缩水了**。
3. 两条一叠加：1672×940 里塞 5 格，每格宽才 ~334 像素，还得塞气泡台词和 30 字字幕 → 必然糊；QQ 再压一次更糊。

**调优处方（按效果排序，都能在 WebUI 改完热生效）**：
1. **`analysis_features.max_topics` 5 → 2 或 3**（最有效）。⚠️ 副作用：群分析报告的话题数会一起变少（同一个开关）。
2. **`image_size` 从 `auto` 改 `2k`（2560×1440）或 `1536x1024`** ——**必须实测上游是否真按这个尺寸返回**。
3. **`aspect_ratio` 从 `16:9` 改 `4:3` 或 `1:1`**（横排每格太窄）。
4. 底部字幕从 30 字压到 12 字内（属插件 prompt 改动）。
5. 验收时**必须用 QQ「查看原图」**看，别把 QQ 压缩当成插件的锅。

**4.12 禁言插件（「丛雨闭嘴 x 分钟」）——已开发 v1.2.0（含手动提前开口），待首启复验**

- **要的效果**：发 `丛雨闭嘴 30分钟` → 她回「好的，接下来我会闭嘴30分钟」→ 这 30 分钟内**什么都不说**（@她、发指令、聊天都不理）→ 到点自动恢复。**口令和回复词都能编辑。**
- **AstrBot 没有原生禁言**（核心配置里没有这种开关）。最接近的是「整会话启停」，但它不能定时恢复、不能回话、还会把插件一起拦掉 → **必须写插件，别用原生会话开关**。
- **为什么插件能拦到不带 @ 的消息**：用 `@filter.event_message_type(ALL)`（覆盖群聊与私聊）、**不注册成命令**——`waking_check/stage.py:219` 会因为 filter 通过而置 `is_wake=True`，所以 L243-244 的 `if not is_wake: stop_event()` 不会拦它。只有 `filter.command` 才要求 `is_at_or_wake_command`。
- **`event.stop_event()` 能拦住后面所有插件和 LLM**（`process_stage/method/star_request.py:37`、`:51` 有 `if event.is_stopped(): break`）。
- **顺序**：priority **数字越大越先执行**（`star_handler.py:26` 按降序排）。本插件优先级必须**高于** `presence_reply`（它用的是 `maxsize + 1`），不然禁言期间她还会先喊「吾辈在！」。
- **规格**：时长支持 分钟/秒/小时，**设个上限**（建议 1440 分钟）；禁言期一切静默；期间再发禁言指令 → **重置计时**；到期用「定时器 + 每条消息惰性判断」双保险（**重启后也能正确恢复**）；状态存 `core/data/plugin_data/<插件名>/` 落盘；默认只禁**当前群**，配置项可切成全局；口令/文案/上限/范围全部 `_conf_schema.json` 可编辑。
- **手动提前开口（已实现，随插件 v1.2.0 入库；旧文档曾记为「待补」）**：禁言期间发**解除口令**（默认 `丛雨说话` / `可以说话了` / `解除禁言`）→ 她**立刻恢复说话**并回一句（默认「好啦，我回来了」）；口令与回复词都可配。
  - ⚠️ **判定顺序**：必须**先查解除口令、再查禁言口令**——「别闭嘴了」这类话里含禁言口令「闭嘴」，顺序反了会被判成**重新禁言**。
  - ⚠️ **位置要求**：解除口令的检查必须放在「静默判断」**之前**——禁言期间的消息本来会被 `stop_event()` 拦掉，写在后面就永远读不到。
- **不做**：不加群内管理/查询命令（用户没提）；不改核心。

**4.13 关键词自动回复插件（**不用唤醒**）——已开发 v1.0.0，待加载复验（任务 27）**

> 用户原话：「这玩意儿还必须要先唤醒？你 AstrBot 插件做不到我是不信的」。**用户说得对，不用唤醒。**

- **官方就支持**：`astrbot/core/star/filter/regex.py:9` 的注释原文——「**正则表达式过滤器不会受到 wake_prefix 的制约**」。用 `@filter.regex(...)` 注册的处理器，**消息一匹配就触发，不需要 @、不需要唤醒词**（注册入口 `core/star/register/star_handler.py:297-309`）。
- ⚠️ **为什么仍必须 `event.stop_event()`（2026-09-16 勘误）**：插件 filter 通过**只会**置 `event.is_wake = True`，**不会**置 `event.is_at_or_wake_command`——核心注释见 `platform/astr_message_event.py:54`；而 LLM 只在 `is_at_or_wake_command` 为真时才被调用（`pipeline/process_stage/stage.py:58`）。所以**不 @ 时 LLM 本来不会接话**；但消息一旦同时 @ 了机器人 / 命中唤醒词，LLM 就会再答一遍 → 命中后**必须** `stop_event()`（它同时阻断后续 handler 与 LLM）。
- **要做成什么**：
  1. **一条规则 = 一个触发词 + 一组回复**。例：触发「我是笨蛋吗」→ 回复候选 `是` / `不是` / `不知道` / `钝角`，**随机挑一个**发。
  2. 回复模式**二选一**：**随机**（从候选里随便挑）或**固定**（永远只回同一条）。
  3. **白名单专属规则**：可以指定某个 QQ 号（或某个群）问同一句话时**只走固定回复**。例：某人问「我是笨蛋吗」→ **只能**回「是」。没被指定的按默认规则（随机）。
  4. **全部可编辑**：触发词、回复列表、模式、白名单，都在 WebUI 插件配置里改，保存即生效。
  5. **支持多条规则共存**。
  6. **不要注册成 `/` 命令**（那样又变回依赖唤醒前缀）。
- 配置：`_conf_schema.json`。官方插件开发文档：`https://docs.astrbot.app/dev/star/plugin-new.html`
- **去向：交开发 Agent（任务 27）**

**4.17 聊天记录提取插件（`astrbot_plugin_chat_extractor` v1.1.0）——修复中（任务 36）**

- **要的效果（用户视角）**：把群里任意一条**合并转发**的聊天记录转给机器人（**引用转发、直接转发都行**），发 `提取 html` 或 `提取 txt` → 机器人回一个文件。html 打开后要**像 QQ 一样**：每条消息一个气泡（头像 / 昵称 / 时间），图片能直接看，**文件要显示真实文件名和大小**，视频给得出链接；聊天记录里**再套着聊天记录**时，外面是一张**能点开的卡片**（显示「共 N 条」+ 前几条预览），点一下展开、再点收起。
- **现状（2026-09-20 规划 Agent 实测）**：端到端已经通了——引用合并转发 → 解析出 8 条 → 导出 html 并发到群里（`core/data/chat_exports/` 今天共 6 个文件）。但有三个问题：
  1. **文件消息显示「未知文件（未知大小）」**：16:29 导出的 html 里出现 4 次。
  2. **没有任何能点开的卡片**：html 里 `.forward-card` 与 `toggleForward` **只出现在 CSS 和 JS 的定义里**，`onclick` 调用 **0 处** → 卡片渲染分支一次都没走到。

- **字段口径（按 OneBot 接收态 + AstrBot 自身适配器的做法，照抄即可）**

  | 段类型 | 接收态字段 | 怎么拿下载链接 |
  |---|---|---|
  | `file` | 名字：`file` / `file_name` / `filename` / `name`（**`file` 最常见，现在的代码漏了它**）；大小：`file_size`；钥匙：`file_id`、`busid` | 群：`get_group_file_url(file_id, group_id, busid=102)`；私聊：`get_private_file_url(file_id)`；或 `get_file(file_id)` 直接返回 `file_name` / `file_size` / `url` |

  | `image` | `file` / `url` | 现状正常，不动 |

- **卡片规格**：顶层被引用的那份合并转发**也要**渲染成卡片（**不是摊平成一片气泡**）；卡片头显示「💬 聊天记录 / 共 N 条 / 前 3 条预览」，点击展开收起、箭头翻转；卡片里的嵌套转发**递归成卡片**；嵌套段两种写法都要认（`type=forward` 取 `data.id`，`type=node` 的内容直接就是）。

## 插件交付标准（README 与图形化面板）

> 📌 **适用范围**：本子项目的**自建插件**（`plugins/` 下 8 个 + 仅运行目录的 `presence_reply`）。**第三方/上游插件**（`qq_group_daily_analysis` / `listen_music` / `repeater` / `limited_repeat`）不套本标准，**不许改人家的文件**。
> 📌 **每个插件必须同时交付 5 件**：代码 + `metadata.yaml` + `_conf_schema.json` + **`README.md`** + **`pages/` 面板**。缺任一视为未完工。
> 📌 **硬门槛**：`metadata.yaml` 的 `astrbot_version` 必须 `>= 4.24.1`（AstrBot 的「插件自定义页面 / Plugin Pages」自该版本起正式支持）。
> 📌 **三不许**：不许只交一个裸配置表单当面板；不许面板依赖外网 CDN（离线/内网必须能开）；文档里不许出现密钥、token、含用户名的绝对路径。

### 1. 目录与命名

```text
astrbot_plugin_<名字>/
├─ main.py / metadata.yaml / _conf_schema.json
├─ README.md                 # ★ 必备
├─ pages/<页面名>/            # ★ 必备：index.html + style.css + app.js
└─ docs/                     # 可选：README 用的截图
```

- 页面目录名会被**直接当作面板标题**（核心里 `title = 目录名`）→ 必须用**英文小写短名**（`library` / `settings` / `overview`），别用中文或长名。
- `_conf_schema.json` 每个配置项都要写 `description` 与 `hint`（人话），配置页仍是用户第一入口。

### 2. 面板的技术约束（v4.26.8 源码实测，照抄不会错）

| 项 | 事实 | 出处 |
|---|---|---|
| 页面根目录 / 入口 | 固定 `pages/`；每页必须有 `index.html`，**没有就不显示该页** | `dashboard/services/plugin_page_service.py:25-26,529` |
| 页面名 / 标题 | 取子目录名 | 同上 `:533-535` |
| 深色主题 | 核心把 `<html>` 改写成 `data-theme="light|dark"` 并注入 `<meta name="color-scheme">` | 同上 `:114-155` |
| 前端桥接 | `window.AstrBotPluginPage`（见下） | `dashboard/plugin_page_bridge.js:207-285` |
| 后端接口 | `self.context.register_web_api("/{插件名}/{短名}", handler, ["GET"], "中文描述")` | 参考 `meme_library/library_ui.py:37-51` |

| 资源路径 | 写相对路径（`./style.css`），核心自动重写成带鉴权 token 的地址（TTL 60s） | 同上 `:583-850` |

| 7 | 危险操作二次确认 | 删除/清空/覆盖必须确认，写明后果**与能否恢复** |
| 8 | 空态 | 「还没有内容」+ 下一步点哪里，不许空白一片 |
| 9 | 加载态 | 按钮禁用 + 文案变化；长任务给进度，不许白屏 |
| 10 | 错误态 | 写「发生了什么 + 怎么办」，不吐堆栈 |
| 11 | 帮助折叠 | `<details><summary>` 放路径、机制这类次要信息 |
| 12 | 深浅色适配 | 用第 4 节的 token，`[data-theme=dark]` 配齐 |

**按插件类型的最小集**：A 有数据型（图库 / 聊天记录）→ 概览 + 网格 + 详情 + 危险确认；B 有配置型（关键词 / 禁言 / 欢迎 / 立flag）→ 当前生效值一览 + 关键项可视化编辑；C 纯行为型（召唤 / 纯唤醒回复）→ 运行状态 + 触发词一览 + 最近触发记录。判据：**打开面板 3 秒内要知道「现在什么状态、我能改什么、弄坏了怎么恢复」**。

```text
│ 帮助折叠 │ 分页 / 空态                                 │
└──────────┴─────────────────────────────────────────────┘
```

> 📐 **参照系（2026-09-20 升级）**：本节的视觉规范**直接对齐 Shinsekai 的官方设计标准**——上游 `RachelForster/Shinsekai` 的 `design.md` 与 `frontend/src/shared/theme/{color,tokens,typography}.css`（v2.3.x，已逐文件核对）。唯一差异：AstrBot 的主题由核心注入 `<html data-theme="light|dark">`，所以下面用**同一套 token、两种生效方式**。

**核心做法：一个种子色，自动长出两套主题**（照 Shinsekai，不要自己拼颜色）

```css
:root{
  color-scheme: light dark;                 /* 与核心注入的 color-scheme meta 配合 */
  --theme-accent: #d4788e;                  /* 唯一需要人工挑的种子色（Shinsekai 当前值） */
  --color-bg-app: light-dark(
     color-mix(in oklch, var(--theme-accent) 7%,  white),      /* 浅色 */
     color-mix(in oklch, var(--theme-accent) 14%, #0d0a0c));   /* 深色 */
}
```

- **页面里只准引用变量，不准写死 hex**；深浅两套用 `light-dark()` + `color-scheme` 自动切换，**再加 `[data-theme=dark]` 一层兜底**（核心必定写这个属性，兜底保证万无一失）。
- 其余颜色同理**按比例派生**（照 `color.css` 的比例抄）：侧栏底 = 种子 12%/18%，面板底 = 4%/10%，输入框底 = 2%/8%，边框 = 24%/26%，悬停边框 = 34%/36%，主文字 = 28% 混深 /18% 混白，次级文字 = 42%/34%。
- **语义色不参与种子派生**（含义必须跨主题稳定）：成功 `#3d8b5e` / `#62d68e`、警告 `#c08030` / `#e8b05c`、危险 `#c24858` / `#ed7a86`、信息 `#3d7a8e` / `#5ec0d6`（浅 / 深）。

**尺度 token（照抄，别自己编数）**

| 类 | 值 |
|---|---|
| 圆角 | 控件 `7px`、面板 / 卡片 `10px`、弹窗与 Toast `12px` |
| 间距 | `4 / 8 / 12 / 16 / 20 / 24`（紧凑模式 12→10、16→14、20→18） |
| 栅格 | 侧栏 `232px` + `minmax(0,1fr)`（抽屉 400px） |
| 内容区 | 最大宽 `1120px`、页边距 `28px`、顶栏 `50px`、底栏 `22px` |
| 字号 | `11 / 12 / 13 / 14 / 15 / 18` |
| 字重 | `400 / 520 / 650 / 700` |
| 行高 | `1.25 / 1.35 / 1.45 / 1.5 / 1.65` |
| 焦点环 | `0 0 0 2px var(--color-accent-border)` |

- **字体**：设置类页面 `"Segoe UI","Microsoft YaHei","微软雅黑",Arial,sans-serif`；对话 / 长文 `"Microsoft YaHei","SimHei",Arial,sans-serif`；等宽 `ui-monospace,Consolas`（放路径、命令）。**不要给单个组件另指定中文字体**，也不要硬编码大号标题。
- **信息层级**：页面标题 `18px/700` → 区块标题 `15px/650` → 正文 `13px/400` → 说明 `12px` 次级色。Shinsekai 是**工具型高密度**界面，**不追大标题、不做卡片套卡片**。
- **响应式**：窗口变窄时靠滚动（内容区可滚动，控件不被截断），不靠隐藏关键控件；侧栏折叠到上方，按钮组允许换行。

**组件规范（同级别的最低要求，逐条都算验收项）**

- **按钮**：底 `#343b48`、悬停 `#394150`、按下 `#232831`、圆角 `7px`、边框 `2px solid #343b48`；主按钮用强调色。必须支持 `disabled` / `loading` / `focus-visible` / tooltip。
- **输入框**：底 `#21252b` 或 `#1b1d23`，悬停与聚焦提高对比，聚焦边框 `#5b657c`，选中文字 `#ff79c6`，内边距 `8px 10px`；必须有错误态、说明文本、禁用态。
- **分段导航**（替代多级标签页）：未选中=透明底白字；选中=强调色文字 + 底部 `2px` 强调线；悬停=轻半透明白底；**只有一页时隐藏导航条**。
- **表格 / 列表**：底色透明或深色（不许亮色表格）；选中态用强调色或 `#404758`；行内按钮只放短标签，批量操作放表格上方或下方；空列表必须有空状态 + 一个明确入口。
- **反馈**：成功与普通提示用 Toast（最大宽 `420px`、圆角 `12px`、约 `4500ms`）；失败、校验错误、破坏性操作用 Dialog / AlertDialog。**危险操作必须有确认弹窗，不能只靠颜色表达风险。**
- **图标**：只用矢量图标；图标按钮必须有 tooltip；图标不单独承载不可理解的含义；图片加载失败要有降级样式，**不许出现空白控件**。
- **可访问性**：点击区域最小 `32px`、主要操作 ≥ `36px`；所有交互控件有 `focus-visible`；弹窗 / 菜单 / 选择器支持键盘与焦点管理；文字在窗口缩放后仍可读、不被按钮边缘裁切。

**交互规矩**：点击 → 禁用按钮 → 出结果（成功 / 失败都出提示）→ 恢复；同一时刻只允许一个动作在跑；耗时任务**不许阻塞界面**（进度走 SSE 推送），加载中按钮必须变 busy；所有功能都能用鼠标完成，快捷键只当加速。

**文案**：设置类文案要短、工具化；按钮用动词（保存 / 导入 / 导出 / 删除 / 生成 / 启动），不用「确定 / 提交」这类空词；错误信息写「原因 + 下一步」，不许只写「失败」；中文与英文之间留空格（`LLM 模型`、`API Key`）；**不许在界面上解释功能原理**，复杂说明收进折叠区或文档。
