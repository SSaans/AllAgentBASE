**4.12 禁言插件（「丛雨闭嘴 x 分钟」）——用户新增（2026-09-16）；规划 Agent 已定稿规格，交开发 Agent**
- **需求（用户原话）**：输入某个指令（例：`丛雨闭嘴 30分钟`）→ 丛雨回「**好的，接下来我会闭嘴x分钟**」→ 之后**无论用什么指令都不会说话**（＝真正的禁言）→ 到时间自动恢复。**指令词与回复词都能编辑。**
- **原生能力核查（用户问「astrbot 应该有原生功能」）**：核心**无禁言 / 静默配置项**。最接近的是**会话整体启停**——`astrbot/core/pipeline/session_status_check/stage.py:24` 调 `SessionServiceManager.is_session_enabled`，值持久化在 `sp`（scope=`umo`，键 `session_service_config.session_enabled`，见 `star/session_llm_manager.py:162-186`），Dashboard 会话管理接口可手动开关（`dashboard/schemas.py:650-653`）。**但它满足不了本需求**：① 无「x 分钟后自动恢复」；② 无回复台词；③ 该 stage 位于 pipeline 最前，`stop_event()` 后**连插件指令一起被拦**、插件自身也收不到消息。→ **须以插件实现，不使用原生会话开关。**
- **可拦截性（已用源码证实，关键三条）**：
  1. **不受 `wake_prefix` 限制**：handler 用 `@filter.event_message_type(GROUP_MESSAGE)`，**不注册为 `filter.command`**。`waking_check/stage.py:181-226` 中非命令类 filter 通过即置 `is_wake = True`（L219），故 `if not is_wake: stop_event()`（L243-244）**不会拦掉本插件的消息**；只有命令过滤器才要求 `is_at_or_wake_command`（`star/filter/command.py:191-192`）。→ **「丛雨闭嘴 30分钟」这类不带 @ 的群消息可被捕获。**
  2. **`stop_event()` 可阻断后续全部 handler 与 LLM**：`process_stage/method/star_request.py:37`、`:51` —— `if event.is_stopped(): break`。
  3. **执行顺序按 priority 数值降序（越大越先）**：`star/star_handler.py:26` —— `self._handlers.sort(key=lambda h: -h.extras_configs["priority"])`。→ 本插件优先级须**高于** `presence_reply`（其值 `maxsize + 1`），否则禁言期间会先蹦出「吾辈在！」。
- **行为规格（规划 Agent 定稿，供开发照做）**：
  - **触发**：消息文本匹配「唤醒词 / 名字 + 禁言口令 + 时长」（例 `丛雨闭嘴 30分钟`）。名字来源沿用运行配置 `wake_prefix`，**插件内不另存一份词表**。
  - **时长解析**：支持 `N分钟` / `Nmin` / `N秒` / `N小时`（N 为正整数）；非法或缺失 → 不触发（是否回错误提示由配置项决定）。**须设上限**（建议 1440 分钟）防误输入。
  - **应答**：回「**好的，接下来我会闭嘴 x 分钟**」（文案可在 `_conf_schema.json` 编辑）。
  - **禁言期行为**：**一切静默**——包括 `presence_reply` 的「吾辈在！」、存图插件的取图、`/群分析`、`/群漫画` 等全部指令与 LLM 对话，**一律不响应**（以 `stop_event()` 阻断）。
  - **期间再收到禁言指令**：**重置计时**（是否再回一次话术由配置项决定）。
  - **到期恢复**：`asyncio` 定时器释放 + **每条消息惰性判断到期**，双保险；后者的意义是**实例重启后仍能正确恢复**。
  - **状态持久化**：落盘至插件数据目录（`core/data/plugin_data/<插件名>/`），重启后禁言仍有效。
  - **范围**：默认**按会话（群）**；提供配置项可切为**全局**（所有群 / 私聊一并静默）。
  - **解除**：因禁言期「什么都不理」，**默认不提供群内解除指令**（只能等到期，或管理员在 WebUI 改配置 / 重载插件）。若开发 Agent 认为可做「白名单解除」，**须用户拍板后再加**。
- **可编辑项（`_conf_schema.json`，参照 4.8 做法）**：禁言口令、应答文案、时长单位支持、时长上限、范围（session / global）、是否允许重置计时、非法输入是否提示。
- **不做**：不新增群内管理 / 查询命令（用户未提）；**不改核心**；不调用原生会话开关。
- **对应任务**：Task.md 任务 26。**去向：交开发 Agent**（按用户指定，统一以 AstrBot 插件形式开发，参照官方文档 `https://docs.astrbot.app/dev/star/plugin-new.html`）。
