## 项目目标

把已经能正常聊天的 AstrBot QQ 机器人（人设「丛雨」）调教成想要的样子，一共三件事：

1. **插件命令能正常用**——群里发 `/分析设置`、`/群分析`、`/群漫画` 这类指令，插件要真的响应。
2. **群总结靠指令触发**——发指令就出当天的群聊总结（话题 / 成员称号 / 金句 / 锐评），用丛雨的口气写。
3. **长回复走转发卡片**——话短就直接发；话太长（超过设定的字数）就打包成 QQ「合并转发聊天记录」卡片发出去。

后来又陆续加了一批小功能（存图、吾辈在、卡片标题、禁言、关键词回复、入群欢迎、使用说明等），规格都写在本文档第四节。

## 核心功能与技术方案

### 功能 1：插件命令正常调用（已达成）

**为什么以前 `/` 命令没反应**：命令过滤器 `astrbot/core/star/filter/command.py:191-192` **第一行就要求** `event.is_at_or_wake_command` 为真，否则直接 `return False`——命令不触发，连报错都没有。这个标志只在三种情况下为真（`pipeline/waking_check/stage.py:102-148`）：① 消息以 `wake_prefix` 里某个词开头；② @ 了机器人 / @全体 / 引用机器人的消息；③ 私聊。

**正确用法**：**@丛雨 + 不带 `/` 的指令正文**，例如 `@丛雨 sid`、`@丛雨 群分析`、`@丛雨 群漫画`。技术勘误（2026-09-16）：当前前缀不含 `/`，@ 唤醒后核心不会额外剥掉正文的 `/`；这些命令也没有带 `/` 的别名。不要靠往 `wake_prefix` 里塞 `/`——实测那样做会让群里所有 `/` 开头的消息都被当成唤醒，跟别的 bot 指令打架。

插件指令：`/群分析`、`/群漫画`、`/分析设置`、`/设置格式`、`/设置模板`、`/查看模板`、`/增量状态`。

### 功能 2：群总结（只靠指令触发，已达成）

用现成插件 `astrbot_plugin_qq_group_daily_analysis`：

- `/群分析` 出报告（话题 ≤5、成员称号 + MBTI ≤8 人、金句 ≤5、质量锐评），格式 `image + text + html`。
- `/群漫画` 出多格漫画。
- 人设要继承丛雨：`analysis_features.keep_original_persona = **true**`（设成 false 会返回 None、人设根本不加载，这是老 Bug 的根因）；`use_plugin_specific_persona = false`。

**4.13 关键词自动回复插件（**不用唤醒**）——已开发 v1.0.0，待加载复验（任务 27）**

  5. **支持多条规则共存**。
  6. **不要注册成 `/` 命令**（那样又变回依赖唤醒前缀）。

#### 4.18-A 追加口径（2026-10-26 15:2x，用户第二次补充）

**① 到 180 分钟直接结束（是结束，不是截断）**
- 轮询里**先判硬上限**：`now - start >= 180 分钟` → 立刻写 `end = start + 180*60`、`duration = 180*60`、`counted = 1`，并发提示「已经到180分钟时长上限了哦！快去休息一下吧！」（@本人；文案 `hard_stop_text` 可配）。
- 这条**优先于**超时提醒：已硬结束的会话不再发「超时提醒」，也不能被 `学完了` 二次结束。
- 计划时长本来就限 180，所以 `planned=180` 的人是准点正常结束，不会落到"超"的分支。

**② 总学习时长也出列表（只列前 20）**
- 输出：
  ```
  你的总学习时长为：{minutes}分钟，数据如下：
  一共学习了{subject}{minutes}分钟！
  一共学习了{subject}{minutes}分钟！
  ```
- 头 `total_header`（`{minutes}` = **全部有效分钟总和**，不等于下面各行相加）、行模板 `total_line`、条数 `total_limit`（默认 20）均可配。
- 排序：分钟降序，同分钟按首次学习时间先后。**今日列表不设条数上限**（一般到不了 20）。

**③ 两个管理命令（不唤醒、不用 @）**

| 命令 | 作用 |
|---|---|
| `/修改技能 xx改为xx` | 把分类「xx」**改名 / 合并**成「xx」：以后照旧说旧名字，统计与展示一律算新名字 |
| `/修改今日时长 xx xx分钟` | 给**今天**的「xx」**加** xx 分钟（增量，不是改成 xx） |

- 正则：`^/?\s*修改技能\s+(.+?)\s*改为\s*(.+?)\s*$`、`^/?\s*修改今日时长\s+(.+?)\s*(\d+)\s*分钟\s*$`。**用 regex、不注册成 command**，这样 `/` 不必进 `wake_prefix`（红线：绝不往唤醒前缀加 `/`）；`/` 写成**可选**，将来万一加了前缀也不会失效。
- 「改名」**只改映射、不改历史记录**：原始 `subject` 原样保留，展示时归一 → 效果是历史一起合并，而且**能撤回**。映射要**压平**：写入 `A→B` 时，把原本指向 A 的旧别名一并改指 B，避免出现 `A→B→C` 链。
- 管理员手动补的时长**不套 5 分钟门槛**（说 3 分钟就记 3 分钟），但要计入今日 / 总列表与关键词分组。

**④ 权限：只认 AstrBot 管理员**
- 判定顺序：① AstrBot 全局管理员（`admins_id` 含该 QQ）→ 放行；② 插件配置 `admin_qq` 白名单 → 放行；③ 其余一律回「如果要改时长、请联系管理员哦！」（`no_permission_text`，可配）。
- **群主 / 群管理员不算**（用户原话「只有我这样的管理员才能改」）。
- 判定出错时 **fail-closed（一律拒绝）**，不许默认放行。

**⑤ 数据（在上一版基础上再加两张表，仍同一个 `study.sqlite3`）**
- `aliases(alias TEXT PRIMARY KEY, canonical TEXT, updated REAL)` —— 运行时改名 / 合并的映射，**优先级高于配置里的 `keyword_alias`**。
- `adjustments(id, scope, uid, date TEXT, subject TEXT, seconds INTEGER, created REAL, by_uid TEXT)` —— 管理员手动补时；`date` 用本地 `YYYY-MM-DD`，统计时并入。
- 统计口径：`有效秒 = Σ sessions(counted=1 且 duration>=300) + Σ adjustments`，再按归一后的 `canonical` 分组。

**⑥ 新增配置项（9 项）**
`hard_stop_minutes`(180)、`hard_stop_text`、`total_header`、`total_line`、`total_limit`(20)、`admin_qq`(list)、`no_permission_text`、`rename_ok_text`、`adjust_ok_text`。

**核心做法：一个种子色，自动长出两套主题**（照 Shinsekai，不要自己拼颜色）

```css
  --theme-accent: #d4788e;                  /* 唯一需要人工挑的种子色（Shinsekai 当前值） */

}
```

### 9. 开发 Agent 作业规则（省 token 版，2026-09-20 用户要求）

- **日志**：插件里**不许**对每条群消息打 INFO（要打就加配置开关，默认关）；只在**命中指令**或**出错**时打，`logger` 用惰性 `%s` 参数、不用 f-string 拼字符串。
- **卡壳**：同一个问题**连续试 2 次没有进展**就停手，把「现象 / 已经试过什么 / 需要什么信息」写清楚**交规划 Agent 先规划**，拿回方案再动手；**不许靠反复热重载试探**（今天这个插件在 12:05–16:29 之间重载了 10 次以上，问题仍在）。
- **取证**：**不许让用户去翻日志、找数据**。要运行期数据就自己造得出证据的场景（隔离测试复现，或加一次性诊断输出跑一遍），拿到证据再改代码。
- **提交**：**一个插件一次提交**；提交前 `git status` 自查——**源码必须入库**（含开发记录，**并入 `CHANGELOG.md`，不另立文件**），运行目录里的日志文件不算交接。

**开工三步（先报后动，没拿到「开工」就不许动手）**

1. **读**：`AGENTS.md` → `DEVELOPMENT.md` → 本文件（含本节）→ 子项目 `Task.md` → `CHANGELOG.md` 最近 3 条；然后**复述**「本次任务号 + 一句话目标 + 照哪一节做」。
2. **列**：本次**只改哪些文件**（逐个路径列出）、是否需要新建文件（**默认不许新建；确需新建先问**）、要跑什么命令、**怎么算做完**（验收标准）。
3. **等**：拿到「开工」二字再动手；**在此之前一行都不许改**。

**收工四段话术（固定格式，缺段就打回重发）**

1. 【任务号】
