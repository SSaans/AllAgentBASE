- [ ] 任务 15：`/群漫画` 支持指定时间段（如「某一天」）——**结论：当前不支持，需开发**
  - 核查：命令定义 `main.py:809-815` 仅接受 `days: int`（**最近 N 天**语义，非某个历史自然日）；底层适配器 `onebot_adapter.py:130-168` 已支持 `since_ts`（起始时间戳），但 `:264` 的过滤条件是 `start_timestamp <= msg_time <= now`——**只有下界、没有上界**，回溯会一直延伸到当前时刻，因此无法只取「历史某一天」。
  - 改造点（交开发 Agent）：① `fetch_messages` 增加 `until_ts` 并透传（`message_repository.py:24` 域接口同步）；② `onebot_adapter.py:264` 过滤补上界；③ `analysis_application_service.py:1169` 手动漫画入口透传；④ `main.py:810` 命令层解析日期参数。另需同步 discord / telegram / qq_official 三个适配器，或明确限定仅 OneBot 支持。
  - 轻量替代：若只需「今天 / 最近一天」，现有 `/群漫画 1` 即可满足，**零开发量**。
  - ⚠️ 备注：拉取受 `max_count` 上限约束，单日消息量超限会被截断，需一并评估。
  - **去向：交开发 Agent**；需用户先确认口径——「最近 N 天」够用，还是必须支持任选历史某一天。
- [ ] 任务 16：转发阈值修改位置——**结论：已答复，属文档补充，无需开发**
  - 字段：`platform_settings.forward_threshold`（QQ 实际档「丛雨丸」当前 = 30）；生效判断 `astrbot/core/pipeline/result_decorate/stage.py:414`（`if word_cnt > self.forward_threshold`）；全局默认值 `astrbot/core/config/default.py:66`（1500）。
  - 改法：在 WebUI 的平台设置中修改并保存即热生效；**直接编辑磁盘 JSON 不会更新运行对象**。
  - 前提：`provider_settings.streaming_response` 必须为 `false`，否则流式结果提前进入发送阶段、跳过该长度判断。
  - **去向：规划 Agent 并入 README 说明章节**。
- [ ] 任务 17：存图功能——**结论：需求口径不明，暂不立项**
  - 两种可能口径，实现路径完全不同：① 归档**群成员发送的图片**（群内聊天图片留存）；② 将机器人**生成的报告 / 漫画**留存到本地指定目录。
  - **去向：等待用户输入** —— 确认口径后再评估走配置、写插件还是独立小工具。
- [ ] 任务 18：被 @ 或叫「丛雨」时立即回复「吾辈在！」——**结论：无内置开关，需小型插件**
  - 核查：AstrBot 唤醒判定在 `pipeline/waking_check/stage.py`（置 `event.is_at_or_wake_command`，唤醒词取 `wake_prefix`，QQ 档为 `["丛雨", "/"]`），但**全仓无任何「唤醒即回固定话术」的配置项**。
  - 方案：编写小插件，监听 `is_at_or_wake_command` 且消息为纯唤醒词 / 纯 @ 时 `yield event.plain_result("吾辈在！")` 后 `event.stop_event()`，阻止后续 LLM 调用造成重复回复。
  - **去向：交开发 Agent**；需用户先确认话术（「吾辈在！」是否固定）与触发边界（@ 也算 / 仅点名算）。
- [ ] 任务 19：关闭 Markdown 输出（当前回复出现大量 `*` 号）——**结论：三条路径，推荐零代码方案**
  - 根因：LLM 输出 Markdown；`result_decorate/stage.py` **不含任何 Markdown 剥离逻辑**，且全局 `t2i=false`，故 `**加粗**`、`## 标题` 等原样发到 QQ。
  - 方案 A（推荐，零代码）：在丛雨人设的 `prompt` 字段（存于 `core\data\data_v4.db`，WebUI 人设编辑可改）追加「使用纯文本回复、禁用 Markdown 语法」约束；系统提示词注入点见 `astr_main_agent.py:519-520`（`# Persona Instructions`）。
  - 方案 B：开启全局 `t2i=true` 将长文本渲染为图片——会改变输出形式，且与 30 字转发分流存在交互，须实测。
  - 方案 C：插件层在发送前剥离 Markdown 符号（开发量最大）。
  - **去向：方案 A 属运行目录改动，须用户本人执行或明确授权；方案 B/C 需用户决策后再交开发 Agent**。
