# 设计

## 按能力拆，不按插件拆

用户关心的是「这机器人能做到什么」，不是「装了哪几个插件」。一个能力可能由多个插件拼起来，一个插件也可能同时支撑两个能力。按能力命名，spec 才对着使用场景。

## 排障记录不进行为规格

BRD 里有大量事故复盘（面板保存失败的三层根因、管理员命令不可用、换机重装）。这些对改代码的人有用，对「系统必须表现出什么」没有约束力。它们留在 README 与历史文件里，需要时查。

## 已知风险

- 五个能力里有三个只在旧机验过，换机后实例从未启动。规格写的是应有行为，不代表已经通过。归档时要标「待首启复验」。
- 关键词回复的唤醒前缀历史上有过变化（`丛雨酱`），规格只写到「命中即回」，具体前缀配置属于实现细节，不进 spec。
- 长回复转卡片的 50 字阈值写在场景里，是为了可测；真调阈值要改规格，不能偷偷改代码。
