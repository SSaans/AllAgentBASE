# 提案

## Why

这个子项目的需求原本堆在一份 1291 行的 BRD 里，功能说明、事故复盘、换机排障、插件源码片段混在一起。想知道「机器人现在到底能做到什么」，只能从头翻。验收时也说不清某条功能该表现出什么，全靠翻聊天记录。

## What Changes

把 BRD 里描述机器人行为的段落拆成五个能力规格，每条要求配可实测的场景。

- 关键词回复：不唤醒也能自动接话
- 群管功能：入群欢迎、禁言、提前解禁
- 使用说明：一条件列出所有能用的功能
- 学习打卡：打卡、连续天数、本群榜单
- 群互动：群分析、群漫画、长回复转卡片

排障过程、换机记录、插件交付标准不进规格，留在 README 与历史文件里。

## Capabilities

### New Capabilities

- `关键词回复`: 群消息命中关键词时自动回复，无需 @
- `群管功能`: 新人入群的欢迎语，以及禁言的设置与解除
- `使用说明`: 一条指令列出机器人当前支持的所有功能
- `学习打卡`: 记录每日打卡、连续天数与本群排行
- `群互动`: 群聊分析、群漫画与长回复的可读化处理

### Modified Capabilities

无。首次为这个子项目建立规格基线。

## Impact

- `BRD.md` 退役，行为进 `openspec/specs/`，用法与现状进 `README.md`
- `Task.md` 停用，进度看 `openspec list`
- `CHANGELOG.md` 并入历史文件后冻结
- 插件源码与运行环境不动
