**实测**：这个会话 1 小时 11 分烧了 $68.82。账单里每一次请求都在**写 7–10 万 token 的缓存**，

接着 Read 一个文件，再 Bash 一下，每一下都要重写一遍缓存。

**四条禁令（说出口就算违规）**

| 不许说 | 为什么 | 该做什么 |
|---|---|---|
| 「由于 token 预算，建议你告诉我是否继续」 | 省钱是你的活，不是让用户做决定 | 自己合批、自己一次做完 |
| 「你自己在群里按步骤验证」 | 用户只负责最后验收，不替你调试 | 本机能跑的自己跑，跑完贴输出 |
| 「我需要先确认问题具体现象」 | 用户已经把现象、截图、复现步骤都给全了 | 读 spec 和 tasks，照着做 |
| 「代码还没真正修复，因为…」 | 这是没做完就交 | 做完了再开口 |

**三条硬规矩**

1. **命令能合并就合并。** 一次 Bash 把要查的全查完（`&&` 串起来），不要一个命令一次调用。
   查五个东西，一条命令搞定，不要五条。
2. **不要整读文件。** 先 `grep` 拿行号，再 `sed -n 'A,Bp'` 取那几行。整读一次几千行，
   既费钱又把没用的东西塞进上下文。
3. **一个功能点从头做到能自测为止**，中间不停下来问「要不要继续」。
