# 设计

## 超管放配置，普管放数据库

超管回答的是「谁是这个插件的主人」，几乎不变，放配置项。用户在面板上能看能改，改完保存即可。

普管回答的是「谁被临时授权」，随时增删，放数据库表。面板直接读表，群里发命令也是写表，两边同一份数据。

两者混在一起会互相拖累：配置改一次要重载，名单随改随生效，节奏不一样。

## 权限判定不碰平台接口

上一轮试过调用平台自带的管理员判定，这条路在本实例上不通，方法不存在，异常被吞掉之后所有管理员命令都是静默失败。

改成纯 QQ 号比对：把发送者的号转成字符串，去两份名单里查。不依赖任何平台能力，也不怕以后平台改接口。

## 面板只有 pages/config/ 会被加载

插件根目录放一份 index.html 不生效，插件读的是 `pages/config/` 那一份。上一轮就是栽在这里：界面写好了、提交了、重载了，用户在界面上什么都没看到。

写在这里，防止下一个人再犯。

## 配置项类型只能用白名单里的

平台只认 `int / float / bool / string / text / list / file / object / template_list / dict` 这十种。写 `number` 或 `integer` 会让整个插件加载失败。

上一轮写错过一次，插件直接起不来。

## 已知风险

- 超管 QQ 改错会让用户自己失去权限。配置里至少要留一个有效号码，删空了要有提示，不能静默保存。
- 名单存在数据库里，删插件数据会丢；配置里的超管不会丢。这个差别要写进 README，别让用户以为名单是永久备份。
- 面板与群命令读的是同一份数据，但刷新时机不同。面板加完人最好顺手在群里发一句「管理员名单」，确认两边一致。
