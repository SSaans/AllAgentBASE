## 一、定位与范围

### 1.1 一句话定位

AllAgentBASE 的**技能进货口**：到外部技能市场（SkillHub、GitHub、ClawHub 等）里找别人已经做成的技能，评估、选型、引进、补齐，最后沉淀进本仓库 `skill/`，供平台内所有 Agent 复用。

### 1.2 与已有资产的关系

| 已有 | 职责 | 与本项目的关系 |
|---|---|---|
| `skill/`（仓库根） | 存放已入库的技能资产 | 本项目的**产出落点**，引进的技能最终落在 `skill/<技能名>/` |
| `skill/规划Agent`、`开发Agent`、`测试Agent` | 平台自身角色的职责卡 | 不涉及。本项目不产出角色卡，只引进外部技能 |
| 根 `BRD.md` | 平台级需求 | 只登记本项目一行索引，需求细节写在这里 |
| 各业务子项目（ALLBot部署、表情包同步等） | 各自的业务 | 需要用某个技能时在自己的 BRD 里声明依赖。本项目只负责供货，不替它们落地 |

### 1.3 为什么现在要这个项目

平台已经有 7 个子项目在跑。每遇到一块「这活儿别人可能已经做成技能了」的事，就得重新搜一遍、重新判断一遍，标准还每次不一样。这个项目把这件事收口到一处：调研方法、评估维度、入库门槛固定下来，之后每来一个新方向，照流程走一遍就行。

### 1.4 本期范围（S1）

- 首期方向：**儿童心理辅导**
- 完成外部技能的调研、候选清单、相似度评估、最匹配项确定与选型论证（本轮已完成，结论见 §三、§四）
- 引进**一项**最匹配的技能，落到本仓库
- 把可复用的评估维度与流程写进本文档（不另建文件）

### 1.5 本期明确不做

| 不做的事 | 原因 |
|---|---|
| ❌ 自研「儿童心理辅导」技能，从零写一套 | 先引进、评估、补齐。等用下来发现确实不够用，再立项自研 |
| ❌ 做医疗诊断、开处方、给用药或停药建议 | 红线 R1，见 §六 |
| ❌ 替代心理咨询师或精神科医生 | 技能提供的是陪伴与引导，专业处置必须回到持证人员 |
| ❌ 批量囤技能 | 本期只引一项，用明白一个再引下一个 |
| ❌ 把技能对外发布、收费分发 | 待用户拍板项 B；未拍板前只在本仓库留档 |

## 二、可复用的调研与评估方法

这一节是本项目的主要资产。以后任何一个新方向都照这套走。

### 2.1 去哪儿找

| 来源 | 特点 | 取用方式 |
|---|---|---|
| **SkillHub**（skillhub.cn） | 中文优先，国内可直连，每个技能上架前过内容合规 + 科恩实验室 + 云鼎实验室三线审核；支持按关键词检索 | 站点检索页与技能详情页；平台也提供 CLI（`skillhub search`） |
| **GitHub** | 上游原始仓库，能看到 SKILL.md 全文、提交历史、许可证、star 数 | 网页检索，或 `api.github.com/search/repositories` 按关键词搜仓库 |
| **ClawHub**（clawhub.ai） | SkillHub 的上游生态，包体量大 | 被 SkillHub 镜像，一般从 SkillHub 取即可 |
| **WorkBuddy 推荐市场** | 本站内置，中文技能，带分类与安装能力 | 站内检索接口 |
| **技能聚合注册表**（claudskills.com、skillsdirectory.com 等） | 收录量大，能快速看到 SKILL.md 摘要与安全评级 | 只当索引用，最终仍回到上游仓库核实 |

### 2.2 怎么评（固定三个维度，加权算总分）

| 维度 | 权重 | 看什么 |
|---|---|---|
| **功能定位贴合度** | 40% | 目标技能做的是不是同一类事。做对话式引导辅导的，和做筛查工具、做临床处置、做知识库的，不是一类 |
| **适用场景贴合度** | 30% | 覆盖的困扰场景是否对上（情绪、行为、人际、学业压力、亲子冲突） |
| **目标用户贴合度** | 30% | 使用者是孩子本人、是家长，还是医生。这一项差异最大 |

三个维度各按 0–100 打分，加权后得相似度（满分 100）。另有两项不进加权、但会改变结论：

- **安全与合规**：上架审核是否通过、有没有许可证、边界声明是否守得住（是否越界做诊断治疗）。越界的一律先排除。
- **成熟度**：版本号、下载量、评分、最近更新时间。成熟度低不等于不能用，但意味着引进后要自己多核一遍。

### 2.3 引进门槛（三条都得过）

1. **有可读的 SKILL.md**，触发条件、工作流程、输出结构、边界声明写得清楚
2. **安全审计通过**（按技能安装安全审计流程走一遍，重点看有没有脚本、外部调用、凭据要求）
3. **许可证与来源可登记**，能写清上游作者、版本、许可证

**1. 青少年成长教练 —— 86 分**

## 四、最匹配项与选型论证

### 4.1 结论

**最匹配：青少年成长教练（`@user_fe828a0e/youth-coach`，来源 SkillHub）。**

### 4.2 为什么是它

1. **辅导对象对上了。** 儿童心理辅导的落点通常是孩子本人。学校心理辅导、儿童咨询室里都是咨询师直接跟孩子谈，家长在外围。youth-coach 就是跟孩子对话的，而且反复交代「不教孩子，先倾听再提问」。
2. **方法有出处。** GROW 教练法、非暴力沟通、成长型思维、身体扫描与接地练习，都是被广泛使用并且公开可查的做法，不是自创话术。
3. **分龄适配做到了。** 6–9 岁每轮不超过三句、用故事和选择题；10–13 岁用完整对话和 GROW 全流程；14–18 岁允许沉默，用苏格拉底式追问。儿童辅导里分龄是硬要求，它真做了。
4. **不越界。** 定位是教练式引导，不诊断、不开药、不下结论，天然贴合 §六 的合规底线。
5. **工具能直接用。** 8 件工具都给了使用时机和示例话术，孩子当场就能用上，不是长篇道理。

### 4.3 它的不足，引进时要补

| 缺口 | 补法 |
|---|---|
| **没有危机识别与转介** | 自伤、自杀意念、虐待、家暴、霸凌致伤这类信号，它不会停机。参照 `mms` 与 `parenting-expert` 的做法加一层：命中即停止辅导流程，转向求助渠道（12355 / 12356 / 儿童心理科 / 110） |
| **成熟度低** | v1.0.0、472 次下载。引进后完整读一遍 SKILL.md，逐条核对内容是否站得住，读起来不对的记进 CHANGELOG |
| **面向孩子本人使用** | 会碰到未成年人对话数据。隐私规矩要先立起来（§六 R3），否则不给孩子直接用 |
| **来源单一** | 只有 SkillHub 一处。按 §2.3 走安全审计，确认包内有没有脚本或外部调用 |

### 4.4 落选与延期（写清什么情况下重新成立，不写「废弃」）

| 候选 | 处置 | 重新成立的条件 |
|---|---|---|
| 育儿大师.Skill | **延期** | 首期方向改为「家长侧支持」，或需要一个覆盖面更广的分龄知识库时，直接引进 |
| 听妈妈的话 | **不单独引进，只借用设计** | 它的危机转介与边界条款并入本次引进的本地化补齐（R2 层） |
| wang-jiqiong | **延期** | 需要家庭教育课程设计或话术样本库时 |
| parenting-psychology | **延期** | 需要英文环境或要对照国外做法时；也可作为本地化的参考素材 |
| child-mental | **延期** | 需要日常情绪与行为筛查（不含疏导）时 |
| 儿童情绪识别分析工具 | **延期** | 出现幼儿园或托管场所的视频接入需求时 |
| 第二代父母 | **延期** | 需要给父母自己做心理支持时，这是另一个方向 |
| managing-child-psychiatry / managing-pediatric-behavioral-health | **延期** | 对接持证精神科医生或儿科医生的工作流时 |

```
skill/<技能名>/
├── SKILL.md          # 上游原文（原样保留，不改一字）
```

## 六、边界与合规红线

这个方向一头连着未成年人，一头连着心理健康，红线要写死。

| 编号 | 红线 |

### 10.3 为什么是它

- 10 项里**只有它把「指导」本身当成职责**。其余全是「帮你出图」或「帮你写提示词」——那是工具，不是指导。
