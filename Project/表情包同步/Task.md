## B. 待办（放行后执行）

- [ ] 任务 5：阶段 1 — Pack 规范与核心引擎（待办）
  - 产出：`manifest.json` schema + 校验器 + Pack 读写库。
  - 产出：CLI `pack init / add / list / validate / export`。
  - 判据：「目录 → Pack → 目录」往返信息零丢失；非法 manifest 能准确报错。
  - ⚠️ 前置：确认本机 **ffmpeg** 可用性（动图转换依赖）；Bash 不可用 → 命令走 PowerShell + Python 绝对路径。

- [ ] 任务 6：阶段 2 — 读取侧打通（三条来源）（待办）
  - ① **QQ 本地缓存**：扫描 NTQQ `personal-emoji/Ori`；修正被存成 `.jpg` 的 GIF 后缀；按「前 24 字节偶数位 ±1」规则还原原创贴纸。
  - ② **`.eif` 解析**：CFB 容器读取 + `Face.dat` 解密以保住**分组与顺序**；注意云端分组（`8213`）无导出入口的变通办法。
  - ③ **TG 贴纸包**：Bot API 下载整包。
  - 判据：三条来源各导入 ≥ 1 个合法 Pack。
  - 参考：`readme9txt/QQEIF-Extractor`、`VanillaNahida/QQFavoriteExtract`、`dogxii/BackupQQEmoji`、`FHPythonUtils/TStickers`（**仅参考思路，不复制源码**）。

- [ ] 任务 7：阶段 3 — 云端同步（待办）
  - 产出：仓库目录规范（分类目录）、`index.json` 索引生成器、拉取/推送流程。
  - 判据：A 机器上传 → B 机器拉取 → 可用；索引能被前端直接消费。
  - ⚠️ 禁止 `git add .`（会带入 `data/` 敏感目录），逐路径显式 add。

- [ ] 任务 8：阶段 4 — 前端（待办）
  - 产出：本地 Web UI（浏览 / 预览 / 打标签 / 勾选 pack → 生成产物 → 显示导入指引）。
  - 判据：不碰命令行即可完成「拉取 → 选包 → 导出 → 按指引导入」。

- [ ] 任务 9：阶段 5a — Telegram 写入（全自动）（待办）
  - 产出：Bot API 建包 / 加贴纸 / 排序；规格校验（512 px、单文件大小、单包上限 120）。
  - 判据：从 Pack 一键生成可用贴纸包，手机端立即可见。

- [ ] 任务 10：阶段 5b — QQ 写入（待办，**含最大不确定项**）
  - 目标 A（优先验证）：能否**生成 `.eif`**？需复现 `Face.dat` 加密回写。社区已有解密侧成果，加密侧需自行推导验证。
  - 目标 B（兜底）：导出「图片文件夹 + 分组说明」，配合 QQ 自带的「添加表情 → 选文件夹 → 新建分组」入口，出图文引导。
  - 判据：**经用户实机导入成功**（任一目标达成即可，目标 A 更优）。
  - ⚠️ 若目标 A 判定不可行，须在本 Task 与 `BRD.md` 第十节明确记录结论与依据。

- [ ] 任务 11：阶段 5c — 微信备料（待办）
  - 产出：按微信规格导出 GIF 组（**≤ 1 MB、≤ 1024×1024**）；输出 PC 端「表情管理 → 添加整套表情」图文引导。
  - 判据：用户按指引在电脑微信上成功导入一套。

- [ ] 任务 12：阶段 6 — 手机侧评估（待办，**只出报告不承诺开发**）
  - 内容：TG 云端可用性（已成立）、QQ 手机导入 `.eif` 的实际路径、自研 App 的成本评估。
  - 判据：出评估报告，由用户决定是否另立项。
