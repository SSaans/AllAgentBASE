# 表情包同步（StickerSync）— 使用说明

> 需求与验收标准见 `BRD.md`；任务看板见 `Task.md`；变更记录见 `CHANGELOG.md`。

---

## 一句话

把散在各处的表情包，收成**「一套 = 一个包」**的标准资产，从 **TIM** 和微信里导得出来、也装得回去。

---

## 这个项目解决什么

TIM 收藏上限是 500（超级会员 1000），微信 300 —— 存满了就得删，删了又舍不得。

**解法不是扩容，而是把"仓库"搬出去**：上千张表情拆成若干主题包放云端，要用哪套就导入哪套，不用了清空。收藏夹从"库房"变成"工作台"。

---

## 先说清楚能做到什么（别抱错期望）

### TIM

| 环节 | 能做到什么 |
|---|---|
| **导出** | ✅ **全自动** —— 直接读 TIM 的表情库文件，把收藏整套提出来 |
| **导入** | ⚠️ **半自动** —— 帮你把包备好，在 TIM 表情面板里挑一次文件就进去了（支持多选，不是一张张点） |

### 微信

| 环节 | 能做到什么 |
|---|---|
| **导出** | ⚠️ **可行** —— 微信缓存里的文件没有后缀、名字是乱码，要靠**看内容**认出是哪张图 |
| **导入** | ⚠️ **只备料** —— 帮你把图处理成微信要的规格，导入还得在电脑微信上手动点一次 |

> 🔴 **做不到的**：一键把表情塞进 TIM / 微信的收藏夹。这两个软件没开这个口子。谁说自己能做到，那是骗子（或者是在动你的 QQ 进程，本项目不干这事）。

---

## TIM 的两个坑（重要，先说）

**坑一：TIM 自己的"导出表情包"功能是坏的。**
社区实测：TIM 导出的 `.eif` 文件是**损坏的**。所以本项目**不走 TIM 的导出功能**，而是直接读它的表情库文件 —— 那个文件是标准格式、**没有加密**，读起来干净可靠。

**坑二：TIM 的表情分组会无缘无故被清空。**
这是 TIM 的老毛病。所以本项目定了一条铁律：

> 🔴 **只要动 TIM 的表情库文件，必须先自动备份，备份失败就不准动。**

绝不原地改，永远是「改副本 → 检查 → 替换」，出问题一键回滚。**这个工具不能变成新的丢数据来源。**

## 表情包长什么样（Pack 格式）

一套表情 = 一个文件夹：

```
魔裁-魔法少女的魔女审判/
├── manifest.json     ← 这套包的"身份证"：名字、分类、标签、每张图的说明
├── cover.png         ← 封面
└── stickers/         ← 表情图片本体
```

导出的成品都是**从这套原始图片现场生成的**，不会丢质量。

**关键设计**：图片是"真相"，TIM 的文件格式只是"产物"。哪天腾讯换格式了，我们换个转换器就行，**收藏一张不丢**。

## 怎么用（预期形态）

在浏览器里打开一个本地页面：

1. 看到有哪些包（按分类排好）
2. 勾选想要的
3. 选目标（TIM / 微信）
4. 点生成 → 拿到文件 + 一份「接下来怎么导入」的图文说明

---

## 三条红线

1. **不碰你的账号** —— 不读进程内存、不提取密钥、不改登录状态。
2. **不动你的原文件** —— 改 TIM 表情库前必先备份，只改副本，出问题自动回滚。
3. **不传播版权内容** —— 表情包大多有版权，Pack 默认只放私有仓库。

---

## 本机执行注意

- Bash 工具不可用（Git Bash 损坏）→ 命令走 **PowerShell + Python 绝对路径**。
- 中文路径必须显式 UTF-8，否则乱码。
- 仓库内**禁止 `git add .`**（会带入 `data/` 敏感目录），必须逐路径显式 add。

---

## 风险速查（完整表见 `BRD.md` 第十一节）

1. 🔴 **TIM 表情库的内部结构没有公开资料** —— 第一步就得实测摸清（只读、用副本）。
2. 🔴 **写 TIM 表情库有丢数据风险** —— 靠「备份 + 副本 + 回滚」三件套兜住。
3. 🔴 **微信没有任何写入接口** —— 微信侧天生只能"备料"。
4. **TIM 已停止维护** —— 靠"图片是真相"的设计扛住。
5. **动图压缩依赖 ffmpeg** —— 本机是否可用待确认。
