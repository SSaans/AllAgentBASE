# 表情包同步（StickerSync）— 使用说明

> 需求与验收标准见 `BRD.md`；任务看板见 `Task.md`；变更记录见 `CHANGELOG.md`。

---

## 一句话

把散在各处的表情包，收成**「一套 = 一个包」**的标准资产，存到云端（GitHub），要用的时候拉下来、生成各平台能直接导入的包。

---

## 这个项目解决什么

QQ 收藏上限是 500（超级会员 1000），微信 300 —— 存满了就得删，删了又舍不得。

**解法不是扩容，而是把"仓库"搬出去**：上千张表情拆成若干主题包放云端，要用哪套就导入哪套，不用了导出清空。收藏夹从"库房"变成"工作台"。

---

## 先说清楚能做到什么（别抱错期望）

| 平台 | 能做到什么 |
|---|---|
| **Telegram** | ✅ **全自动** —— 一条命令建好贴纸包，手机电脑都自动同步 |
| **QQ** | ⚠️ **半自动** —— 帮你把包备好（`.eif` 文件或图片文件夹），导入那一下要你点 |
| **微信** | ⚠️ **只备料** —— 帮你把图片处理成微信要的规格，导入还得在电脑微信上手动操作 |

> 🔴 **做不到的**：一键把表情塞进 QQ / 微信的收藏夹。这两个软件没开这个口子，谁说自己能做到，那是骗子（或者是在动你的 QQ 进程，本项目不干这事）。

## 表情包长什么样（Pack 格式）

一套表情 = 一个文件夹：

```
魔裁-魔法少女的魔女审判/
├── manifest.json     ← 这套包的"身份证"：名字、分类、标签、每张图的说明
├── cover.png         ← 封面
└── stickers/         ← 表情图片本体
```

导出的成品（QQ 的 `.eif`、TG 的贴纸包、微信的图片组）都是**从这套原始图片现场生成的**，不会丢质量。

## 怎么用（预期形态）

在浏览器里打开一个本地页面：

1. 看到云端有哪些包（按分类排好）
2. 勾选想要的
3. 选目标平台（QQ / TG / 微信）
4. 点导出 → 拿到文件 + 一份「接下来怎么导入」的图文说明

Telegram 那一步会直接帮你建好，剩下两个跟着说明点几下就行。

---

## 三条红线

1. **不碰你的账号** —— 不读进程内存、不提取密钥、不改登录状态。
2. **不乱删东西** —— 不动你的 QQ 缓存目录，任何删除先列清单再问。
3. **不传播版权内容** —— 表情包大多有版权，Pack 默认只放私有仓库。

---

## 本机执行注意

- Bash 工具不可用（Git Bash 损坏）→ 命令走 **PowerShell + Python 绝对路径**。
- 中文路径必须显式 UTF-8，否则乱码。
- 仓库内**禁止 `git add .`**（会带入 `data/` 敏感目录），必须逐路径显式 add。

---

## 风险速查（完整表见 `BRD.md` 第十节）

1. 🔴 **QQ 的 `.eif` 能不能程序化生成** —— 还没验证，是最大不确定项。
2. 🔴 **QQ / 微信没有写入接口** —— 决定了本项目"半自动"的天花板。
3. **腾讯版本一改，路径和格式就可能漂** —— 靠"以图片为真相"的设计扛住。
4. **动图转换依赖 ffmpeg** —— 本机是否可用待确认。
