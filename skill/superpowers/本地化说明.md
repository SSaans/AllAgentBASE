# superpowers 本地化说明

上游：https://github.com/obra/superpowers （`obra/superpowers`，MIT，v7.0.1）
落盘：2026-10-27，整包原样拷入，`skills/` 下 15 个子技能一字未改。

## 这是什么

一套写给编码 agent 的工程方法论，15 个可组合技能。它管的是**怎么写代码**：先问清要做什么，再出规格、出计划、红绿 TDD、系统化排查、完成前先跑验证。

## 强制引用（开发 Agent 必守）

写代码、改 Bug、评审、收工之前，按下表读对应技能。`skills/using-superpowers/SKILL.md` 是总入口，开工先读它。

| 场景 | 必读技能 |
|---|---|
| 开工第一件事、判断该用哪些技能 | `skills/using-superpowers/SKILL.md` |
| 要做新功能、改行为、动结构 | `skills/brainstorming/SKILL.md` |
| 需求已清楚，要拆多步任务 | `skills/writing-plans/SKILL.md` |
| 动手写实现（任何功能或修 Bug） | `skills/test-driven-development/SKILL.md` |
| 遇到 Bug、测试失败、行为不符预期 | `skills/systematic-debugging/SKILL.md` |
| 准备说「做完了 / 修好了 / 通过了」 | `skills/verification-before-completion/SKILL.md` |
| 收工合并、决定怎么落地 | `skills/finishing-a-development-branch/SKILL.md` |
| 请人或被请做代码评审 | `skills/requesting-code-review/`、`skills/receiving-code-review/` |
| 有 2 个以上互不依赖的任务 | `skills/dispatching-parallel-agents/SKILL.md` |

技能里有清单的，逐条建 todo，做完一条勾一条。宣称完成之前必须先跑命令拿到输出，不许凭印象说「应该没问题」。

## 和仓库现有规矩的优先级

**仓库的 `AGENTS.md`、`DEVELOPMENT.md`、`skill/开发Agent/SKILL.md` 优先于本包**。上游自己也写了这条（`using-superpowers` 末节：用户指令优先于技能）。

两处已知冲突，按仓库口径办：

1. **`[x]` 谁能勾**。superpowers 让实现者自己勾任务；本仓库只允许测试 Agent 勾 `[x]`。开发 Agent 用 superpowers 的清单推进，但状态写进 `Task.md` 的「待复验」，不自行关闭。
2. **子 agent 并行**。`subagent-driven-development` 与 `dispatching-parallel-agents` 要求有子 agent 能力。当前环境没有就降级为单线执行，用 `executing-plans` 代替，不要假装派了子 agent。

## 三条使用限制

- **关掉 telemetry**。brainstorming 的可视化页会从官网加载 logo 并带上版本号。本机设 `SUPERPOWERS_DISABLE_TELEMETRY=1`，或在会话里不启用该可视化功能。它不上传代码与提示词，但没必要留着。
- **可视化服务默认不起**。`brainstorming/scripts/server.cjs` 会起本地 HTTP 服务，默认只绑 `127.0.0.1`，有 Origin 校验。只在用户明确要「看图讨论」时启动，用完即停。
- **不改上游文件**。要改行为就写在本文件或本地补丁里，不动 `skills/` 下的原文，方便以后整体替换升级。

## 与 OpenSpec 的分工

OpenSpec 定「写什么」，superpowers 定「怎么写」。两份都要用时，先走 OpenSpec 出规格与任务，再用 superpowers 的 TDD 与验证纪律落地。细则见 `skill/openspec/本地化说明.md`。

## 升级方式

重新下载 `https://codeload.github.com/obra/superpowers/tar.gz/refs/heads/main`，整目录替换 `skills/`，再核对本文件的技能表有没有增减。
