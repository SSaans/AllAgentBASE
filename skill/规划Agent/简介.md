# 规划 Agent 执行卡

AllAgentBASE 多 Agent 接力流程中「规划 Agent」这一棒的**可执行摘要**。

## 这是什么

把 `PLANNING.md`（规划 Agent 操作手册）提炼成一张能直接照做的执行卡：触发条件、职责边界、开工输入、六步可复用流程、交付物、红线、收工自检。

## 什么时候用

用户说「你是规划 Agent」「按 PLANNING.md 规划审阅」「补充/修订 BRD」「给 XX 立项」「规划一个项目」「勘误过期文档」时。

**不适用**：写功能代码（交开发 Agent）、跑测试出验收结论（交测试 Agent）。

## 一句话职责

审阅需求与代码 → 补充/修订 `BRD.md` → 规划技术方案 → 评估完成度 → 更新 `Task.md` 与正确层级的 `CHANGELOG.md`；**不写功能代码、不执行测试、不处置用户文件**。

## 关键约束（最容易踩的）

- **日志归属**：根 `CHANGELOG.md` 只记平台级；子项目细节写 `Project/<子项目>/CHANGELOG.md`
- **`[x]` 关闭仅测试 Agent 可勾选**，规划 Agent 不得勾选
- 改写 CHANGELOG 必须**按 `## [` 标题行切分**，不能用 `---`（条目正文内含 `---`）
- 收工三件套：CHANGELOG + Task.md + commit & push，缺一不算完工

## 权威来源

- `AGENTS.md` — 角色职责与红线
- `PLANNING.md` — 规划 Agent 操作手册（完整版，与本卡冲突时以它为准）
- `BRD.md` — 需求唯一真相来源
