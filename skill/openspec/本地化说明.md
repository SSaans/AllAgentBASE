# openspec 本地化说明

上游：https://github.com/Fission-AI/OpenSpec （`Fission-AI/OpenSpec`，MIT，CLI v1.15.0）
落盘：2026-10-27，`skills/` 下 12 个子技能原样拷入，一字未改。

## 这是什么

一套规格驱动开发（SDD）的工作流。它管的是**写什么**：先产出一份人和 agent 都能审的规格，再照着规格拆任务、写实现、验收、归档。代码动手之前，需求必须先落成可审的文件。

配套 CLI 已装好，`openspec --version` 输出 1.15.0。命令在 PATH 里找不到时，用绝对路径 `C:\Users\Unbox\.workbuddy\binaries\node\versions\22.22.2-6\openspec.cmd`。

## 强制引用（开发 Agent 必守）

接到新功能、新改动时，先走 OpenSpec 流程，再动手写代码。

| 阶段 | 用哪个技能 | 干什么 |
|---|---|---|
| 想清楚 | `skills/openspec-explore/SKILL.md` | 摸清问题、澄清需求 |
| 立项 | `skills/openspec-new-change/SKILL.md` | 建 change，按步产出提案 |
| 一步到位（需求已明确） | `skills/openspec-propose/SKILL.md` 或 `openspec-ff-change` | 一次生成提案、设计、规格、任务 |
| 实现 | `skills/openspec-apply-change/SKILL.md` | 按 tasks 逐条实现，逐条勾 |
| 修订计划 | `skills/openspec-update-change/SKILL.md` | 需求变了就改产物，不闷头改代码 |
| 验收 | `skills/openspec-verify-change/SKILL.md` | 对照规格核实现是否真做到 |
| 归档 | `skills/openspec-archive-change/SKILL.md` | 完成后并入主规格 |

**顺序不可跳**：没有 change 就不许开写。实现中需求变了，先回去改产物，再改代码。

## 初始化策略（重要）

**只在具体子项目根目录 init，不在 `E:\AllAgentBASE` 根目录 init。**

本仓库根已有自己的 `BRD.md` / `Task.md` / `CHANGELOG.md` 三件套，再叠一套 `openspec/` 会变成两套账，谁也不是准。子项目内部要规格驱动时再就地初始化：

```bash
cd "E:/AllAgentBASE/Project/<子项目>"
openspec init --tools agents --language zh-CN
```

`--tools` 可填 `agents`（通用）、`codebuddy`（本机 WorkBuddy）、`claude`、`codex` 等，逗号分隔可填多个。`--language zh-CN` 让后续产物默认写中文。

初始化前先看一眼目标目录：`openspec init` 会清理旧版本残留，遇到同名 `openspec/` 会刷新而不是覆盖规格。拿不准就先跑 `openspec list --json`，看 `root` 是 `null` 还是已有对象。

## 和 BRD / Task 的关系

- `BRD.md` 是**规划产物**，写需求、边界、验收标准，归规划 Agent。
- `openspec/` 是**实现规格**，写某个 change 的提案、设计、任务，归开发 Agent 在自己子项目里用。
- 两者不互抄。子项目 BRD 里的验收标准可以被 `openspec-propose` 引用成规格，但不要在两边各写一份改来改去。

## 三条使用限制

- **只让 CLI 操作本项目**。技能里 `allowed-tools` 限定为 `Bash(openspec:*)`，别用文件工具手搓 `openspec/` 里的产物。
- **不代用户决定初始化位置**。仓库根、家目录、临时目录都不许自动 init；`root: null` 时按技能里的分支停下问，不要顺手建。
- **不改上游文件**。要调行为写在本地文件里，`skills/` 保持原样，方便整包升级。

## 与 superpowers 的分工

OpenSpec 出规格、拆任务、验规格；superpowers 管 TDD、调试、评审、完成前验证。先后关系：OpenSpec 定做什么，superpowers 管怎么做好。细则见 `skill/superpowers/本地化说明.md`。

## 升级方式

CLI：`npm install -g @fission-ai/openspec@latest`。
技能：重新下载 `https://codeload.github.com/Fission-AI/OpenSpec/tar.gz/refs/heads/main`，替换 `skills/`，核对技能表增减。
