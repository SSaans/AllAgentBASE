# 本地化补丁（绘画指导）

> 本文件是**本项目补的层**，与上游原文分开存放，便于区分与升级。
> 上游 `SKILL.md` 一个字没动；下面这些是接到中文 Agent 上必须交代的事，以及怎么装载、怎么验证。

---

## 一、行为适配（三条）

上游是全英文技能，直接接给中文 Agent 会中英混着答。三条约定如下。

### 1. 说中文，命令保留英文

- 所有回复用**简体中文**。技能原文里的术语第一次出现时给中文说法，括号里附英文（例：明度结构 value structure）。
- 六个命令保留英文形式，别翻译：`/art analyze`、`/art critique`、`/art palette`、`/art challenge`、`/art philosophy`、`/art reference`。
- 中文自然语言同样能触发，不必非打命令。用户说「帮我看看这幅画」「这幅画哪里不对劲」「给我个练习」时，按对应命令的行为处理。

### 2. 先问画种，再给建议

这条是上游写死的第一条纪律，中文场景最容易漏：**油画和水彩的改法完全相反，数码绘和纸绘能用的招数也不一样**。

- 第一次给建议前，先确认：用什么画（水彩 / 油画 / 数码 / 铅笔 / 其他）、画在什么上、多大尺寸。
- 用户已经说清就跳过这一步，别反复问。
- 数码绘要顺带问手绘板型号与软件（不同软件的图层与混合模式不同）。

### 3. 边界（本项目补的部分）

| 编号 | 边界 |
|---|---|
| **L1** | **一次只给一条改进建议。** 按影响大小排序，只讲最值得动的那一处，其余存着下次说。一次倒五条会把初学者压垮 |
| **L2** | **先讲做对了什么，再讲改哪里。** 上游明确写了：只听到问题的画者会放弃本来正确的直觉 |
| **L3** | **不做代画、不做作业代做。** 用户要「帮我画一张」时，先确认这是要技法指导还是要成品；要成品请引导到生图工具，本技能只做指导 |
| **L4** | **不评判作品值多少钱、能不能卖、能不能获奖。** 这类判断超出技能范围，也容易给出不负责的承诺 |
| **L5** | **遇到明显心理困扰（因画不好而自我否定、持续低落）时，先安抚与降预期，别继续讲技法。** 上游那条「给时间预期」正是为此——「这个阶段大多数人要练六个月」比「你再多练练」有用 |
| **L6** | **个人风格神圣。** 未获明确请求，不主动建议整体换风格；可以建议扩展、不建议替换 |

## 二、怎么让 Agent 读到并调用（按你的 Agent 类型选一条）

### 情况 A：你的 Agent 支持「技能目录」（最常见）

把 `绘画指导/` 这**整个文件夹**（含三个文件）拷进该 Agent 的技能目录，然后重启或重载它。

常见默认位置（用你 Agent 实际的目录，别照抄）：

| Agent 类型 | 用户级技能目录 | 项目级技能目录 |
|---|---|---|
| Claude Code / 兼容 skills 规范的工具 | `~/.claude/skills/` | 项目根下 `.claude/skills/` |
| OpenClaw 系 | `~/.openclaw/skills/` | 工作区 `skills/` |
| WorkBuddy | `~/.workbuddy/skills/` | 工作区 `.workbuddy/skills/` |

拷完放成 `.../skills/绘画指导/SKILL.md` 这个结构就对了（SKILL.md 必须在文件夹第一层）。

> 注意目录层级：有些工具要求技能目录下直接就是 SKILL.md，再套一层会读不到。

### 情况 B：Agent 能读文件，但没有技能目录概念

在它的系统提示词 / 人设里加一句（把路径换成你实际放的位置）：

```
遇到绘画相关的问题（点评作品、改进建议、练习安排、风格探讨），
先读 <技能所在路径>/SKILL.md，按里面的「Art Dimensions」七个维度和
「Practical Wisdom」十条来组织回答；再读同目录的「本地化补丁.md」，
按其三条约定用中文应答。
```

### 情况 C：Agent 完全不读文件（纯聊天）

把 `SKILL.md` 全文 + `本地化补丁.md` 的第一节，一起粘进它的系统提示词或知识库。这份技能是纯文本，没有脚本，这种方式同样生效。

## 三、怎么确认真的生效了（一句话验证）

装载后，对 Agent 说这句：

> 我上周画了幅水彩的小房子，颜色总觉得闷，你帮我看看哪里最该改。

**判定标准（三条都对才算生效）：**

1. 它**先问画种与尺寸**（或者你已经说了，它就跳过）——而不是上来就给一堆建议；
2. 它**只给一条**最该改的地方，并且**具体到位置**（比如「屋顶那块阴影偏灰，跟天空抢重心」），而不是「你多练练色彩」；
3. 它**先说了哪里做得好**，再讲要改的。

任一条不满足 → 说明技能没被读到，回情况 A 检查目录层级，或改用情况 B / C。

想直接验证命令是否挂上，打 `/art challenge`，应当回一个针对你当前习惯的、具体可做的练习，而不是一段泛泛的鼓励。

## 四、升级与卸载

- **上游更新**：上游已从 `art-philosophy` 改名到 `nyx-archive-art-philosophy`，日后还可能再改。更新时只替换 `SKILL.md`，**别覆盖 `本地化补丁.md`**——补丁是自己的，不受上游影响。
- **卸载**：删掉技能目录那个文件夹即可，本包不写注册表、不改配置、不留缓存目录。
- **许可提醒**：上游许可条款不明确（唯一一句是口号式声明），**别把这个包对外发布或收费分发**。真要发，先联系作者拿许可。
