# 本地化补丁（绘画基础训练）

> 本文件是**本项目补的层**，与上游原文分开存放，便于区分与升级。
> 上游 `SKILL.md` 一个字没动；下面这些是接到 Agent 上必须交代的事。

---

## 一、和「绘画指导」怎么分工（最容易撞车的一处）

本仓库现在有两个绘画技能，触发词高度重叠，装载时必须约定清楚谁管哪一段。判断依据是**用户要的是「练」还是「看」**。

| 用户想干的事 | 交给谁 | 理由 |
|---|---|---|
| 我该练什么、给我安排训练、每天画多少、基础怎么补 | **本技能**（绘画基础训练） | 它产出分阶段练习任务与自检方法 |
| 看看我这幅画哪里该改、这张的构图问题、颜色闷不闷 | **`skill/绘画指导/`** | 它按七个维度做点评，一次只给一条 |
| 涉及比例、透视、明暗、人体结构这类基本功的具体练法 | **本技能** | 技法教学是它的本职 |
| 聊风格选择、创作意图、艺术史上怎么处理这个问题 | **`skill/绘画指导/`** | 它管判断力与意图，不管步骤 |

两个可以接力。典型链路是先用绘画指导点出问题，再用本技能给出针对这个问题的练习任务。谁先谁后按用户当场的问题定，不要两个一起上。

**一条硬规矩。** 用户拿作品来求点评、且他没法把话说具体时，别硬用本技能接。本技能看不到图，接了就只会得到一堆「请描述你的作品」。这种情况优先转 `skill/绘画指导/`，或者先帮他把话问具体。

## 二、行为适配（三条）

### 1. 就用中文，不必翻译

上游原文本来就是中文，直接照用。术语第一次出现时按中文说法给，需要时括号附英文。

### 2. 视力和图像能力如实交代

上游写死了「点评基于文字描述」。接上多模态 Agent 后，这条容易被忽略——模型明明能看图，技能却按看不见写。

处理办法：**看得到就正常看图，看得到的内容照常用；但不要凭空编出图里没有的细节**。用户没发图、只给文字描述时，就按上游的流程走，先帮他把问题问具体（线条抖、比例不对、透视歪，到底哪一项）。

### 3. 坚持度优先于技法密度

上游的 FAQ 与最佳实践都指向同一件事：习惯比突击重要。应答时守住这几条。

- 用户中断了几天回来，先说「正常，别背包袱」，再给当天任务，不要顺势加量。
- 用户说画得丑，照上游口径回应，初期丑是正常的，让他留作品做三个月对比。
- 每次只安排能当天做完的量。一次给一周计划会把初学者压垮，除非用户明确要周计划。

## 三、边界（本项目补的部分）

| 编号 | 边界 |
|---|---|
| **L1** | **不做代画、不接「帮我画一张」。** 要成品请引导到生图工具，本技能只出练习任务与方法 |
| **L2** | **不接美术联考、艺考应试。** 上游已把「专业美术考试备考」列入不适用场景，理由是需要面对面应试训练。用户要这个，如实说明并建议走培训班 |
| **L3** | **不做作品质量鉴定与估价。** 判断值多少钱、能不能卖、能不能获奖，超出范围 |
| **L4** | **不贬低用户水平。** 上游明确写了不做贬低性评价，也不制造焦虑、不与他人不当比较 |
| **L5** | **不承诺进度。** 说「大多数人在这个阶段要练多久」可以，说「几天就能画好」不行 |
| **L6** | **不收集用户作品与个人信息。** 训练计划与反馈只服务当次对话，不留存 |

## 四、怎么让 Agent 读到并调用（按你的 Agent 类型选一条）

### 情况 A：Agent 支持「技能目录」（最常见）

把 `绘画基础训练/` 整个文件夹（含四个文件）拷进该 Agent 的技能目录，重启或重载。

| Agent 类型 | 用户级技能目录 | 项目级技能目录 |
|---|---|---|
| Claude Code / 兼容 skills 规范的工具 | `~/.claude/skills/` | 项目根下 `.claude/skills/` |
| OpenClaw 系 | `~/.openclaw/skills/` | 工作区 `skills/` |
| WorkBuddy | `~/.workbuddy/skills/` | 工作区 `.workbuddy/skills/` |

放成 `.../skills/绘画基础训练/SKILL.md` 这个结构就对了，SKILL.md 必须在文件夹第一层。

> ⚠️ **一个已知门槛**：上游的 `SKILL.md` **没有 frontmatter**（开头是 `# Drawing Foundation Training`，没有 `---` 包裹的 `name` / `description`）。按 skills 规范强校验 frontmatter 的装载器会装不上，或者装上了不认触发。碰上这种情况，在本目录另建一个 `SKILL.local.md`，只写最小 frontmatter（`name: 绘画基础训练` + 一句话 `description` + `trigger`），正文写「按同目录 `SKILL.md` 执行」。上游原文照旧不动，补的这一层算本地化。

如果把两个绘画技能都装上，建议同时把本文件第一节的分工规则放进 Agent 的常驻提示里，否则容易两个技能抢答。

### 情况 B：Agent 能读文件，但没有技能目录概念

在它的系统提示词里加一句（路径换成实际位置）。

```
遇到「我该练什么 / 给我安排绘画训练 / 基础怎么练」这类问题，
先读 <技能所在路径>/SKILL.md，按它的三步走（水平评估 → 制定计划 → 执行反馈）
产出当日练习任务；再读同目录的「本地化补丁.md」，按第一节的分工规则
判断该不该转给「绘画指导」技能。
```

### 情况 C：Agent 完全不读文件（纯聊天）

把 `SKILL.md` 全文加 `本地化补丁.md` 的第一节，一起粘进系统提示词或知识库。纯文本技能，这样同样生效。

## 五、怎么确认真的生效了（一句话验证）

装载后，对 Agent 说这句。

> 我是零基础，想学画画，从哪开始？

**判定标准，三条都对才算生效。**

1. 它回的是**具体可执行的当日任务**，有数量、有时间（比如画 50 条直线、30 个圆，每组几分钟），而不是一段「多练习就会进步」。
2. 它**问了你的可用时间和工具**（铅笔还是数位板），并说明任务会按你的反馈调整。
3. 它**没有**承诺「几天就能学会」。

任一条不满足就说明技能没被读到，回情况 A 检查目录层级，或改用情况 B、C。

想顺带验证分工是否生效，接着问「那我这张画哪里该改」，看它是不是把点评那部分交给绘画指导，或先把你的描述问具体。

## 六、升级与卸载

- **上游更新**：只替换 `SKILL.md` 与 `_meta.json`，**别覆盖 `本地化补丁.md`**，补丁是自己的，不受上游影响。
- **卸载**：删掉技能目录那个文件夹即可。本包不写注册表、不改配置、不留缓存目录、不常驻进程。
