# Token 节省与缓存友好执行卡

AllAgentBASE 全平台的**降本纪律**：怎么读写文档才不烧 token、哪些内容适合被缓存、哪些动作会让缓存全废。

## 这是什么

把「prompt 缓存 + 分层记忆 + 滑动窗口 + 模型分流」这套运行时优化理论，**逐条判定**后映射到本仓库：

- **能落地的**：文档三层结构（稳定 / 半稳定 / 易变）、固定前缀策略、滑动窗口（＝CHANGELOG 15 条上限 + 归档）、按需定向读、要点式交接 —— 全部写细，可直接照做
- **落不了的**：向量数据库召回、消息分类器、运行时缓存标记 —— **明确标注不适用**，并给出等价替代（Grep 即召回、任务分流即分类器），**不硬塞**

## 什么时候用

要在本仓库做大范围读写（通读文档、扫描代码、整理日志、写交接），或用户提到「省 token」「多用缓存」「上下文太长」「降低成本」时。

## 一句话结论

**先 Grep 定位再定向读、新内容追加不改写、稳定前缀一个字节都别动、日志到 15 条就归档。**

## 关键红线（做了等于缓存全废）

- 为排版好看重排章节顺序、改写标题措辞
- 把日期/状态这类易变信息插进正文中段
- 在多个文件里复制同一段长规则（应该用指针引用）
- 每轮通读全量 CHANGELOG / 全仓文件

## 配套

三个 Agent 执行卡（`skill/规划Agent`、`skill/开发Agent`、`skill/测试Agent`）各含一节精炼的「Token 纪律」，指向本卡。

## 权威来源

- `AGENTS.md` — 角色职责、日志归属
- 三本 SOP — 各角色完整流程
