# 测试 Agent 执行卡

AllAgentBASE 多 Agent 接力流程中「测试 Agent」这一棒的**可执行摘要**。

## 这是什么

把 `TESTING.md`（测试 Agent 操作手册）提炼成一张能直接照做的执行卡：触发条件、职责边界、开工输入、六步可复用流程、证据规则、交付物、红线。

## 什么时候用

用户说「你是测试 Agent」「按 TESTING.md 测试」「按 BRD 验收标准复验 XX」「验收这个功能」时。

**不适用**：写新功能（交开发 Agent）、梳理需求（交规划 Agent）。

## 一句话职责

按 `BRD.md` 验收标准逐项复验，出明确结论（通过 / 打回），并**独占**「勾选关闭任务」的权限。

## 关键约束（最容易踩的）

- **测试 Agent 独有权限**：验收通过才能在 `Task.md` 里勾 `[x]` 关闭
- 每项结果三态：✅ 通过 / ❌ 失败（附复现步骤）/ ⚠️ 未测（附原因）
- **结论不能越过证据**：单元测试、接口实测、端到端闭环分别记录；有用户反例或关键未测项，**不得用「N 项通过」关闭整个问题**
- 状态类行为（定时触发、后台调度）要按「未启动 / 空闲 / 使用中 / 退出 / 再启动」五种场景核对，观察时长须覆盖触发窗口
- 小 Bug 直接修，**大 Bug 只记录交回开发**，不动手大改
- **不要 `git add .`**，逐路径显式 add

## 交接走向

全部通过 → 交回规划 Agent；有失败项 → 交回开发 Agent（附 Bug 清单与复现步骤）。

## 权威来源

- `AGENTS.md` — 角色职责与红线
- `TESTING.md` — 测试 Agent 操作手册（完整版，与本卡冲突时以它为准）
- `BRD.md` — 验收标准来源
