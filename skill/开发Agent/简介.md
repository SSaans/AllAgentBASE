# 开发 Agent 执行卡

AllAgentBASE 多 Agent 接力流程中「开发 Agent」这一棒的**可执行摘要**。

## 这是什么

把 `DEVELOPMENT.md`（开发 Agent 操作手册）提炼成一张能直接照做的执行卡：触发条件、职责边界、开工输入、五步可复用流程、自测与收尾要求、交付物、红线、收工硬检查。

## 什么时候用

用户说「你是开发 Agent」「按 DEVELOPMENT.md 开发」「根据 Task.md 实现 XX」「修这个 Bug」「部署这个项目」时。

**不适用**：需求还在梳理（交规划 Agent）、按验收标准出结论（交测试 Agent）。

## 一句话职责

照 `BRD.md` 与 `Task.md` 写代码、自测、留证据，把任务推到「待复验」；**不改需求、不跳自测、不删测试的 Bug 记录、不猜需求**。

## 关键约束（最容易踩的）

- **进度实时写 Task.md**，不攒到收工——实测证据（时间、trace、用户确认）比结论值钱
- **自测 ≠ 正式验收**，`[x]` 关闭留给测试 Agent
- **仓库外代码**（如桌宠运行目录）改动必须把摘要写回本仓库并推送——仓库是唯一真相来源
- **证据留在克隆副本里没推回主仓库 = 交接失败**（真实踩过）
- 收工硬检查：`git status` 干净 + `git ls-remote origin main` == 本机 `HEAD`
- **不要 `git add .`**，逐路径显式 add（仓库常有他人未提交改动）

## 附带资源

`DEVELOPMENT.md` 附录「**Git 推送与网络应急手册**」——三 Agent 通用，记录了推送失败三种形态与唯一可信判据，收工推送前建议先读。

## 权威来源

- `AGENTS.md` — 角色职责与红线
- `DEVELOPMENT.md` — 开发 Agent 操作手册（完整版，与本卡冲突时以它为准）
- `BRD.md` / `Task.md` — 需求与任务来源
