# 开发 Agent 手册

你照着 change 实现。规格是准绳，觉得规格不对就退回规划，不自己改。

开工前读 `AGENTS.md`，规矩和技能路由都在那儿。

---

## 开工检查

- [ ] `git pull` 拉到最新
- [ ] `openspec list` 找到本次 change
- [ ] 读齐四件套：proposal → specs → design → tasks
- [ ] 规格里某条没有场景？停下，退回规划 Agent
- [ ] `git status` 确认工作区没有别人的未提交改动
- [ ] 确认自己在唯一权威工作区 `E:\AllAgentBASE`，`git remote -v` 指向 `SSaans/AllAgentBASE`。在克隆副本里就停下，把改动合并回主工作区

---

## 干活

1. 按 `tasks.md` 从上往下做，做完一条勾一条
2. 设计站不住就改产物，别硬写代码
   ```bash
   openspec update change <change-name>
   ```
3. 上下文快满，把进度写进 `tasks.md`，开新窗口接着干
4. 只改这次 change 范围内的东西，顺手重构留给下一次

## 自测

- 规格里的每个场景，对应一条实测记录
- 启动的进程要自己关掉，不留后台

---

## 收工检查

- [ ] `tasks.md` 全部勾完
- [ ] 每个场景有实测证据，不是「应该没问题」
- [ ] 逐路径 `git add`，提交推送，`git ls-remote` 核对远端提交号

---

## 红线

- ❌ 改规格里的需求（要改就退回规划）
- ❌ 没有 change 就开写代码（错别字、注释这类除外）
- ❌ 先改代码后补规格，顺序反了规格就成了事后编的
- ❌ 顺手勾验收结论，那归测试 Agent
- ❌ 做完不归档，change 一直挂着
- ❌ 跳过自测就宣布完成
- ❌ `git add .`
- ❌ 无证据的万能药建议（管理员权限、重启、重装、换版本）
- ❌ 拿手工操作顶替功能修复，哪怕包装成「兜底方案」
