# 设计

## 为什么不留只读文件

只读文件的问题在于它需要被人记住「不能写」。Agent 每换一个会话就要重新学一遍这条规矩，而文件本身没有任何机制阻止写入。删掉之后，规则从「记得别写」变成「根本没有这个东西」，判断成本降到零。

## 历史为什么不搬去别处

内容已经在 git 里。把同样的叙事再誊一份到 `openspec/` 会造出两份不一致的记录，正好是这个仓库一直在治的毛病。

## 未完成的活怎么接

原任务看板里有五条技能资产的复验一直没做。这些是真活，不能跟着文件一起消失，所以另立 change `verify-skill-assets`，用 `openspec list` 就能看到它还没完。

子项目那三条（万有引力待拍板、ALLSkill 待开工、全惠惠平面设计待开工）不属于平台层的活，写进各自 README 的待办小节，等项目真正启动时再立 change。

## 风险

- 历史文件的删除不可逆（本地有备份，git 里有原文）。以后想找某条事故复盘的完整叙述，只能翻 git。
- 清理引用要覆盖十个子项目，漏一处就留一个死链，所以清理后统一扫一遍。
