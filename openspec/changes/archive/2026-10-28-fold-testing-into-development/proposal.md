# 提案

## Why

用户从来不叫测试 Agent。他的实际做法是自己跑一遍，觉得不对就找规划聊，改完再交开发。三个角色里，测试这一棒在他手上是空转的。

空转的代价很实在。`AGENTS.md` 里「验收结论只有测试 Agent 能写」写死在八处，每个 change 归档前都要卡在这里，要么等他开口叫一个从不存在的角色，要么干脆跳过闸门二。规矩挂在那里没人执行，比没有规矩更糟。

同时「实现完了不等于验过了」这个担忧是真的。原设计靠「换一个人来验」防它，现在没人可换，这道防线得换个方式撑住。

## What Changes

把测试合并进开发。角色从三个变两个，测试这个动作不消失。

- 开发 Agent 的活扩展到「实现 + 自测 + 留验收证据」
- 删除独立的测试角色，包括它的手册与执行卡
- 验收结论的写法改掉：谁验谁写，逐条对应 Scenario，带实测动作与结果
- 用户保留最终放行权，他点头才算过

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `交接规矩`：角色从三个变两个；勾选与验收结论的归属重新划分

## Impact

- 改 `AGENTS.md`（角色速查、职责对比、change 分工、勾选边界、常见违规、路由表）
- 改 `README.md` 的流程链
- 合并 `agents/测试.md` 进 `agents/开发.md`，原文件退役
- 合并 `skill/测试Agent/` 进 `skill/开发Agent/`，原目录退役
- 不动任何子项目的规格与代码
